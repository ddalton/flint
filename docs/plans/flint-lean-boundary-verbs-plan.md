## 1. Motivation and non-goals

### 1.1 The two problems

1. **Torn published views.** The barrier publishes on a clock (`floor_secs`, default 60 — `lean/sidecar/src/lib.rs:113-125`, run loop `bin/flint_sync.rs:143-174`). A multi-file logical change (write `model.json`, then `model.json.index`) can straddle a tick: the bucket manifest cites the first file and not the second. Every downstream reader — checkout of a new pod (`checkout.rs:38-161`), HITL GET through the gateway, a sibling cluster's sync — can observe a mid-logical-change state. Nothing in the shipped protocol lets the application say "here is a coherent point."
2. **Unbounded cross-pod freshness, agent-side.** A pod learns the bucket advanced only when its own barrier's HEAD-tick notices the manifest ETag moved (`barrier.rs:203-237`), and the *live tree* converges only via inbox consume at the next barrier or via the `sync` verb — which today is CLI-exec only (`bin/flint_sync.rs:71-141`) and **cannot even be exec'd beside a live `run` loop**, because the state-dir flock refuses a second process (`state.rs:87-137`, test `second_sidecar_on_one_tree_refuses`, `tests.rs:556`). An agent inside the app container has no way to ask for a sync and no way to learn there is news.

### 1.2 Why the filesystem is the interface

The app container ships **unchanged** — that is load-bearing in the lean plan. No HTTP client, no CLI binary, no library can be assumed in the app image. The only interface every agent is guaranteed to have is the shared workspace mount itself. So the boundary verbs are *files*: the agent touches `.flint/publish` or `.flint/sync`, and reads `.flint/publish.ack`, `.flint/sync.ack`, `.flint/remote.seq`. Richer doors (localhost/UDS HTTP, a gateway verb) are layered *over* this file protocol (§2.5), never instead of it.

**Trust statement (review: security-dos).** Every file in `.flint/` is writable by every process sharing the mount — the emptyDir is mounted into the sidecar *and* every app container (`inject.rs:84-98`), and there is no path the sidecar can write that the app cannot. Therefore **acks are advisory coordination signals, not attestations**: an in-pod process can forge `.flint/publish.ack`. The authoritative durability signal is a remote read the pod cannot forge — gateway `GET /status` (`last_cited_seq`) or the manifest itself. The agent contract must say this verbatim; agent libraries MUST NOT treat an ack as proof of remote durability for decisions that destroy local state. (A per-container MAC secret was considered and rejected: the pod has no intra-container trust boundary to anchor it — a process that can forge the ack can already tamper with the workspace bytes the ack describes. §9 SD-3.)

### 1.3 Non-goals (v1, DECIDED)

- **No interception.** No FUSE, no LD_PRELOAD, no fsync tracing. fsync-derived boundaries are named as a *future* coherent-point source for strict-journal synergy (§2.4.3) and are out of scope here.
- **No privilege.** Sentinels are ordinary files in the pod's own mount, writable by the workspace's own containers only.
- **No new remote surface for the app.** The app container gains zero network reachability. The optional UDS/localhost door (§2.5) is pod-internal and opt-in; the optional gateway verb is for HITL, not the app.
- **No change to one-writer-per-subtree.** The lease/claim/rotation machinery (`lease.rs`) is untouched — except that this tranche must *renew* the lease from its new arms (D12, §2.1a); the claim/rotation protocol itself is unchanged.
- **No history/branching.** A boundary is a coherent point in a single linear manifest sequence, not a snapshot, tag, or branch.
- **No scoped publish.** `.flint/publish` covers the whole workspace. (Scope exists only on `sync`, §2.2.)

## 2. Design

### 2.0 The `.flint/` control namespace — the precondition for everything else

**Shipped hazard (verified):** the scanner skips *only* the root-level `.flint-sync` state dir and symlinks (`scan.rs:32-50`). A workspace-local `.flint/` directory **is scanned today** and would be published to `<prefix>/files/.flint/...`. The gateway already reserves `.flint/` on the HTTP side (`path_ok`, `gateway.rs:110-118`), and the bucket-side control namespace is `LEAN_DIR = ".flint/lean"` (`lib.rs:59-65`) — but the scan does not.

**DECIDED — D0:** reserve `.flint/` at the workspace root as the local control namespace, symmetrical with the gateway's reservation:

1. `scan::walk` skips a root-level `.flint` directory exactly as it skips `.flint-sync`.
2. `scan::classify` **exempts `.flint/`-prefixed baseline paths from delete eligibility.** Without this, upgrading a workspace that legally published `files/.flint/...` under the old sidecar would see those paths absent from two consecutive scans (`scan.rs:83-108` two-scan rule) and publish their *deletion* — an upgrade must never delete data. Legacy `.flint/` citations are carried forward frozen (never re-uploaded, never deleted by us) and a one-time warning conflict record (`conflicts.jsonl`) names them.
3. `checkout` never materializes `files/.flint/...` citations into the local `.flint/` dir (they'd collide with control files); they are left cited and a conflict record names them.
4. **Pre-existing-data pre-flight (review: ops-fleet).** Reserving `.flint/` is a **breaking change** for a workspace already using it as data: its writes silently stop publishing, and — worse — files literally named `.flint/publish` or `.flint/sync` would be *consumed* (renamed away) by the sentinel poll: a data grab from a non-participating workspace. Rule: at `run` startup, if the baseline or manifest cites any `files/.flint/**` path, **or** `.flint/publish`/`.flint/sync` exist before `capabilities.json` has ever been written for this tree, sentinel consumption is **disabled** for the workspace: the poll arm never arms, `capabilities.json` reports `"verbs": []` with `"reason": "preexisting-flint-paths"`, and the condition `SentinelVerbsActive=False` (reason `PreexistingFlintPaths`) surfaces it fleet-visibly — not just a jsonl line inside the pod. The CRD knob `sentinels: auto|off|force` (§2.6) overrides: `force` requires the operator of record to accept the consumption behavior explicitly. The upgrade notes name the `.flint/**` publish-stop as breaking. Drill leg B22.

This is the keystone: with D0 in place, sentinel files can exist without ever entering the upload set, and workspaces that never touch `.flint/` see the scan get marginally *cheaper*.

### 2.1 Publish sentinel — `.flint/publish` and `.flint/publish.ack`

**The verb.** The agent creates or overwrites `.flint/publish`. Two forms:

- **Bare touch** (empty file): boundary with anonymous identity.
- **JSON body:** `{"nonce": "<agent-chosen string ≤128B>", "note": "<free text, ≤4KiB>"}`.

**Agent-side write discipline (review: crash-takeover).** Agents writing a JSON body MUST write-temp-then-rename *within* `.flint/` — a plain `open+write` racing the consume rename continues into the moved inode and leaves a torn body in the pending file. The sidecar tolerates this (below), but the contract requires atomic writes and the agent-library docs say so.

**Semantics (DECIDED — D1):** a sentinel with mtime T means *"everything ordered-before T is a coherent point; publish it."* The guarantee is **at-least**: the barrier that acknowledges the sentinel begins its scan strictly after consuming it, so every write visible on disk at consume time is in the published set. Writes racing the upload read are covered by the shipped pre-read-stat re-queue valve (`barrier.rs:672-680`) — the published state may include *later* bytes for a racing file, never earlier ones. The mtime-granularity residual of the scan (`scan.rs:73-75`) applies to the boundary guarantee too (§3). **Corollary (review: security-dos):** a sentinel-honoring barrier may never skip a dirty file for cost reasons — a cooldown that excluded a file's latest bytes would falsify the ack. Cost is bounded by *deferring the barrier* (D3), never by thinning its contents.

**Consumption discipline (DECIDED — D2, revised) — the inbox pattern, mirrored.** `consume_inbox` is exactly-once via integrate → persist → drop-in-CAS, idempotent between (`barrier.rs:67-157`, `inbox.rs:165-186`). The sentinel copies it with rename in place of CAS:

1. **Consume** = `rename(".flint/publish", ".flint-sync/publish.pending.json")` (same filesystem — both under the workspace emptyDir — so rename is atomic), wrapping the body with `{consumed_mtime_unix_ns, consumed_at, nonces: […]}`. A bare touch gets an empty nonce list entry. **Type check first (review: security-dos):** the poll `lstat`s the sentinel and consumes only `S_ISREG` — a FIFO, directory, symlink, or socket at the sentinel path is skipped with a warning conflict record (a FIFO would block the body read forever; the read is also bounded at 64 KiB). **Settle-before-consume (review: crash-takeover):** the poll arm never consumes while a pending file exists — a surviving pending must be honored, acked, and retired first, otherwise the rename would clobber the old pending record and orphan its nonces forever. Coalescing happens *inside* the pending record: while a pending sentinel waits for the min-interval, subsequent touches are consumed by appending their nonces to the standing pending record (rename onto a temp, merge, rewrite pending), never by overwriting it.
2. **Honor** = renew the lease (D12), then run one full fused barrier (`run_barrier`, all 7 steps, `barrier.rs:180-469`). In gated mode this barrier is a *citation* pass (§2.4). **Torn-body rule (review: crash-takeover):** an unparsable or oversize pending body is honored as a bare-touch boundary (nonces empty, mtime from the file) with a warning conflict record — never a wedge, never a silent drop. A pending file, parsable or not, is "work": it defeats the skip-on-no-diff fast path exactly as `repairs_pending` does (`barrier.rs:203-206`).
3. **Ack** = after the barrier's manifest CAS installs and the baseline rewrite completes (step 7), write `.flint/publish.ack` via atomic write-then-rename:

```json
{
  "status": "ok",                      // "ok" | "refused-fenced"  (review: crash-takeover)
  "nonces": ["…", "…"],                // EVERY coalesced nonce covered (bounded 32, oldest dropped)
  "sentinel_mtime_unix_ns": 1756…,     // latest covered touch — bare-touch agents match on this
  "seq": 4132,                         // manifest seq installed by the honoring barrier
  "manifest_etag": "…",
  "boundary": "sentinel",              // "sentinel" | "sentinel-deferred" (budget, D3)
  "completed_unix": 1756…,
  "observed_epoch": null,              // set on refused-fenced: the epoch that fenced us
  "report": { "uploaded": 12, "deleted": 1, "parked": 0, "consumed": 2, "no_change": false }
}
```

   The ack carries the **full covered-nonce set** (review: security-dos): under coalescing, an agent whose nonce rode behind a later touch would otherwise never see its nonce and re-touch in a loop, feeding the storm the rate limit exists to prevent.
4. **Retire** = delete `.flint-sync/publish.pending.json` *after* the ack rename.

**Refused acks (review: crash-takeover — this was the largest protocol hole).** The draft had no negative ack anywhere; deposal stranded sentinels forever. Shipped behavior: `run_barrier`'s `verify_not_deposed` returns `Fenced` (`barrier.rs:190`), `run_loop` exits on it (`bin/flint_sync.rs:161`), `main` exits 0 (`bin/flint_sync.rs:84`), and the restarted claimant spins in `Waiting` against the live successor — while the agent container keeps running, its pending sentinel never answered, `capabilities.json` still advertising live verbs. Rules:

- On `Fenced` during honor (or during the drain, D10), the sidecar writes the ack with `status: "refused-fenced"` — echoing nonces/mtime, naming the observed epoch — **before** the fenced exit, then retires the pending file.
- The restarted process, upon `claim_step` observing a foreign live holder with a surviving pending file, writes/refreshes the refused ack (it can never honor).
- On fence, `capabilities.json` is atomically rewritten with `"state": "fenced"` and `"verbs": []`, and `gauges.json` says the same, so agents stop touching sentinels on a zombie.
- **In-loop sync honor is gated on `verify_not_deposed`** (review: crash-takeover): `Sidecar::sync` has no lease/epoch check at all (verified — `sync.rs` contains none; today it is only reachable via `claim_then`, which claims first). A straggler consuming a sync sentinel between deposal and its next cooperative fence would apply the successor's manifest onto its zombie tree and ack SUCCESS. The select-arm honor path calls `verify_not_deposed` first and refuses with `refused-fenced` on failure.
- Model product 1 gains the deposal arm; drill leg B18.

**Crash matrix (review: crash-takeover — the draft's per-crash-point prescriptions were wrong and are replaced).** The draft said a restart finding pending-and-no-ack could "write the ack from the pending record against the current baseline seq (the install already happened)". It cannot know that: pending-present-and-no-matching-ack is the *same observable state* for crash-mid-step-2 (before the manifest CAS — baseline is rewritten only at step 7, `barrier.rs:443-456`) and crash-after-step-7; acking from persisted state in the first case asserts publication of writes that never uploaded, violating `Inv_AckImpliesCited`. **One uniform rule replaces the matrix:** on restart, pending + no ack whose nonces/mtime match ⇒ **always run a full barrier** (idempotent; AdoptOwn/recent-uuids covers a half-published set, `barrier.rs:564-638`), then ack with *that* barrier's installed seq — never ack from persisted state alone. Crash after ack before retire → retire on restart (nonce match, no second barrier — the ack already names a real install). Settle-before-consume (rule 1) guarantees a fresh sentinel can never clobber the surviving pending. Pod *replacement* loses the pending file with the emptyDir — and also the workspace; the successor's checkout starts from the last coherent manifest, and the agent (also restarted) re-declares. Both hazards are TLC mutations in product 1: ack-from-stale-baseline must violate `Inv_AckImpliesCited`; consume-over-pending must violate `Inv_NoNonceOrphan`.

**Coalescing + rate limit (DECIDED — D3, revised).** Sentinel consumption is a poll tick (default 1 s, env `FLINT_SYNC_SENTINEL_POLL_SECS`) that `lstat`s exactly two fixed paths — no inotify dependency in v1, no directory scan, ~2 lstats/s when idle. **Loop structure (review: security-dos — the draft's structure was self-starving):** the shipped run loop recreates `tokio::time::sleep(floor)` inside `select!` on every iteration (`bin/flint_sync.rs:151-155`), and `lease::renew`'s only call site is that floor arm — a third arm completing every 1 s would win every iteration, perpetually reset the floor sleep, and the lease would **never renew**: the sidecar deposes itself into the 7,591-PUT straggler class by construction. The loop is rewritten on **independent non-resettable `tokio::time::interval` timers** — renewal interval, floor interval, poll interval — so no arm's readiness can starve another. Drill leg B17 proves renewal under sentinel storm.

Rate limiting is two-level, enforced sidecar-side (never on agent honor):
- `sentinelMinIntervalSecs` (default 5): a consumed sentinel arriving sooner than this after the previous sentinel-honoring barrier waits; touches during the wait coalesce into the pending record (D2.1), and the ack is cumulative — any ack whose `sentinel_mtime_unix_ns ≥` your touch covers your boundary, because a later boundary strictly contains an earlier one.
- `sentinelHourlyBudget` (default 60) (review: security-dos): min-interval alone still permits 17,280 forced barriers/day — a 12× request amplification per hot small file, agent-controlled (§7). When the hourly budget is exhausted, sentinel honors **defer to the next floor tick**: the boundary is still honored by a real barrier (D1's corollary — contents are never thinned), the ack is stamped `boundary: "sentinel-deferred"`, and `gauges.json` exposes the exhaustion. Sustained forced-barrier rate is thereby capped near cadence-equivalent; bursts up to the budget are prompt.
- **The budget meters work, not calls (DECIDED — D3.1, new: the hot-loops no-regression rule).** A counted budget charges a hot 2 GiB checkpoint the same one unit as a 4 KiB file, so a storming agent could drive `dirty_bytes × 60/hour` of extra upload while staying inside a green budget — a regression on the one performance sub-axis lean currently maxes (hot loops score 5 precisely because a tight local loop's republish is *coalesced by cadence*; sentinels un-coalesce it on demand). Rule: a sentinel-honoring barrier consumes

      units = 0                                    if it published no bytes (no-diff honor)
              max(1, ceil(published_bytes / 64 MiB))   otherwise        (`whole_put_max`, `lib.rs:69`)

  Three consequences, all intended: the **common agent shape is untouched** — a boundary per logical step with a small diff costs 1 unit, 60/hour exactly as drafted, and the hot *small* file keeps the 1-unit-per-honor cap the security-dos review asked for; the **hot large file self-limits** — a 2 GiB dirty set costs 32 units, so ~2 sentinel honors/hour before honors defer to the floor and the workspace degrades to *precisely today's cadence behavior*, which is the definition of no regression; and a **no-diff sentinel storm stays free and prompt** (one HEAD + an ack rename), because the budget exists to bound work and a no-diff honor does none — min-interval remains its only bound, and §7 prices its HEAD ceiling.
  The bound this buys is statable and workload-independent: **sentinel-driven published bytes ≤ `sentinelHourlyBudget × whole_put_max` per hour** (3.84 GiB at defaults) on top of whatever cadence would have published anyway. Metering is post-hoc — bytes are known when the barrier completes — so the cap is enforced with **one barrier of overshoot**, bounded by the dirty set (and by `stagedBacklogCap*` in gated mode). Stated rather than rounded away.

**Mixed-fleet hazard (must be loud in agent docs):** on an **old** sidecar, `.flint/publish` is a regular file — it gets scanned and *published to the bucket* (the D0 hazard). Agents MUST check the capability marker (§2.5) before touching any sentinel.

#### 2.1a Lease-renewal discipline (DECIDED — D12, new) (review: crash-takeover, security-dos)

The lease token advances only via `lease::renew`, and a standby judges the holder dead after `QUIET_POLLS=6` observations 10 s apart (`lease.rs:24,66`) — a ~60 s quiet threshold. The draft's sentinel and citation barriers never renewed; on the plan's own 1-hour-floor drill fixture, a workspace publishing continuously via sentinels would present a token quiet for up to an hour and any replacement claimant would depose the *live* writer within ~60 s — mid-honor, feeding the refused-ack path unnecessarily. Rules:

1. Every barrier-triggering arm — floor tick, sentinel honor, sync honor, citation pass (both sources), drain — calls `lease::renew` first, exactly as the floor arm does today.
2. Independently, a **heartbeat renewal interval** fires at `min(floor_secs, (QUIET_POLLS×10)/2) = min(floor, 30) s`, decoupling liveness signaling from publish cadence entirely. (At the default floor=60 the shipped renew cadence *equals* the takeover threshold — already racy; this closes that too.)
3. Renewal runs on its own non-resettable interval (D3) — structurally immune to arm starvation.

Cost: at floor=60 this changes the renewal PUT cadence from 60 s to 30 s — priced in §7, and the one deliberate default-posture request increase in this plan (+1 PUT/min/workspace), bought for takeover-safety of the shipped protocol as much as the new arms. Drill leg B17.

### 2.2 Sync sentinel — `.flint/sync` and `.flint/sync.ack`

**The verb.** `.flint/sync`, empty or `{"nonce": "…", "scope": ["inputs/", "shared/config.json"]}`. Same consume/honor/ack/retire discipline as §2.1 (own pending file `.flint-sync/sync.pending.json`, own min-interval sharing `sentinelMinIntervalSecs`, same type-check/torn-body/settle-before-consume/refused-fenced rules, same budget pool).

**Why in-loop:** the flock forbids a second `flint-sync` process beside a live `run` (`state.rs:116-136`), so the sentinel is consumed inside the run loop, invoking the existing `Sidecar::sync` (`sync.rs:22-143`) at the sidecar's own safe point — never concurrent with a barrier, never in background, and **only after `verify_not_deposed` passes** (D2). This *preserves* the design invariant that sync mutates the live tree only when invoked: the agent's touch is the invocation, placed at an agent-chosen safe point.

**Scope semantics (DECIDED — D4, with a correctness rule that is not optional):** scope is a list of path prefixes (and exact paths); remote adds/changes/deletes apply only to in-scope, locally-clean paths, exactly as today's whole-tree rules (`sync.rs:31-143`: scan-first, locally-dirty wins, deletions only on clean paths, every skip a conflict record).
**The rule:** a scoped sync advances `inst_base` **only for the paths it actually applied or verified in scope**, and leaves `baseline.seq` / `baseline.manifest_etag` **untouched**. Rationale: `inst_base` is the three-way merge base (`state.rs:28-48`; baseline≠instBase is a load-bearing model finding, `lean/formal/README.md:81-85`). If a scoped sync advanced the whole `inst_base` to bucket-current, every out-of-scope foreign change would look already-integrated to the next merge (`manifest.rs:118-124`) and would be **silently lost from the inbox flow forever**. With D4, out-of-scope changes remain "foreign" and flow through the normal merge → inbox → consume path at the next barrier (`barrier.rs:368-467`), untouched from today. Whole-tree sync (no scope) behaves exactly as shipped, including advancing seq/etag. Because D4 rewrites the per-path semantics of the exact object the model has refuted naive designs on twice, it is **modeled before code** — product 4, §4 (review: model-drill).

**Scope validation + write containment (review: security-dos).** Scope is agent-controlled JSON driving writes by the credential-holding sidecar, and the write path it invokes — `write_file_atomic` (`barrier.rs:702-724`, also used by consume and checkout) — does `create_dir_all(parent)` + `fs::write` with no `O_NOFOLLOW` and no root-containment check, while the scanner skips symlinks (`scan.rs:40-43`) so a planted symlink is invisible to the sidecar. An unprivileged app that plants `inputs -> /root/.aws`, lands a HITL object at `inputs/<path>`, and drops a scoped sync turns the sidecar into an on-demand arbitrary-file-write primitive outside the workspace. Rules (Phase 2 gate; the hardening also covers the pre-existing checkout/consume exposure):
- `write_file_atomic` becomes containment-safe: openat-style parent walk (or canonicalize-and-verify-prefix) refusing any target that escapes the workspace root or traverses a symlink component.
- Scope entries are normalized and matched on **path-component boundaries** (`"in"` never matches `internal/`); entries whose parents are symlinks are refused with a conflict record; scope list bounded (≤64 entries, each ≤1 KiB).

**Ack payload:** the existing `SyncReport {applied, deleted, conflicts, seq}` (`sync.rs:22-28`, already `Serialize`) extended with `status`, `nonces`, `sentinel_mtime_unix_ns`, `scope`, and `out_of_scope_foreign: <count>` (changes seen but deferred to the inbox flow). **The conflict report rides the ack in full** — "never a silent winner" must survive the file transport: every dirty-vs-remote skip appears as a `ConflictRecord` in `sync.ack`'s `conflicts[]`, in addition to `conflicts.jsonl` as today.

**Phantom-conflict rule on re-honor (review: crash-takeover):** `sync()` applies foreign files one by one and saves the baseline only at the end (`sync.rs:87-101,140`). A crash mid-apply followed by re-honor makes already-applied paths scan dirty against the stale baseline and refuse with `sync-dirty` conflicts — the ack would report conflicts for paths whose local bytes *are* the remote bytes, and those paths would then re-publish as spurious generation bumps. Rule: before declaring a `sync-dirty` conflict, compare content identity (crc64 of the local file vs the remote entry's `crc64_b64`, already in `LeanEntry`); byte-identical paths are treated as applied — the baseline entry advances instead of a conflict recording. Unit test injects the mid-sync crash.

### 2.3 `.flint/remote.seq` — the news ticker

**DECIDED — D5, revised.** The sidecar maintains `.flint/remote.seq` (write-then-rename), updated from information it already has — **zero added bucket requests**:

- At the no-change fast path, the barrier already HEADs the manifest (`barrier.rs:214-236`; HEAD-not-GET is the measured 27 s/1.3 GiB lesson). The HEAD's `ObjectMeta.meta` carries the `flint-gen` stamp, and `cas_write` stamps `generation = m.seq` (`manifest.rs:92-99`) — so the observed remote seq comes off the existing HEAD for free.
- At every full barrier completion, from the installed manifest itself.

```json
{ "observed_seq": 4140, "observed_etag": "…", "integrated_seq": 4132, "updated_unix": 1756…,
  "sync_requested_unix": 1756…, "sync_requested_by": "ci@example" }
```

`observed_seq > integrated_seq` means "there is news you have not integrated — consider dropping a `.flint/sync` sentinel at your next safe point." The agent polls one **local** file: no network, no client, no credentials.

**The two request fields are advisory news, not commands (DECIDED — D14, §8 Q4).** `sync_requested_unix`/`sync_requested_by` are set from the gateway's `sync_request` inbox field (§2.5) and mean *"a HITL/CI party asked you to pull"*. The sidecar **performs no tree mutation on receipt** — it moves the ticker and nothing else; the agent drops `.flint/sync` at its own safe point and gets the normal scoped-sync ack and conflict records. A request older than the agent's last integration is stale and self-clears (`sync_requested_unix < integrated_unix`). Advisory has a real cost, stated: an agent that never reads the ticker never pulls, and the honest escalation for that case is pod recreation — checkout re-materializes the tree from the cited manifest, coherent by construction — not a remote-forced rewrite. **Heartbeat rule (review: ops-fleet — the draft's two claims contradicted):** the draft said the file is written only on content change *and* that `updated_unix` is the staleness tell — on an idle-but-healthy workspace those can't both hold (an agent couldn't distinguish "no news" from "sidecar dead"). Rule: `updated_unix` is refreshed on **every successful HEAD tick** (a local rename — zero bucket cost); `observed_seq`/`observed_etag` change only when they change. Agent-side staleness rule, in the contract: `updated_unix` older than 3×floor ⇒ sidecar or proxy problem — check `gauges.json`. Freshness of *news* is bounded by the floor tick; if the proxy is unreachable the ticker goes *stale, never wrong* (the gateway-vs-proxy failure split, chaos C8/C12, is unchanged: remote.seq survives a gateway outage, dies-stale with the proxy).

### 2.4 Gated manifest advance — durability split from visibility

#### 2.4.1 The three modes (DECIDED — D6)

`boundaryMode: cadence | hybrid | gated`, **default `hybrid`**.

- **cadence** — exactly today: every floor tick runs the fused barrier (upload + cite in one pass). Sentinels still work (a sentinel triggers a fused barrier); this mode exists as the explicit "old behavior" escape hatch. (Propagation caveat: switching a live workspace's mode requires pod recreation — §2.6.)
- **hybrid (DEFAULT)** — the fused barrier runs at every floor tick *and* at every consumed publish sentinel, **whichever comes first**. Citation never waits: published-view freshness is never later than today's, and boundaries only add coherent points. There is **no separate eager lane in hybrid** — uploads and citations coincide, so the uncited-object set is exactly today's crash-window set (the intent journal's keys, `state.rs:61-71`), bounded by one cadence and reconciled by the shipped AdoptOwn/recent-uuids machinery (`barrier.rs:564-638`). This is what makes constraint (b)'s byte clause true by construction under defaults; the request clause is D3's budget (review: security-dos). Drill leg B16 is the regression proof that the rewritten loop still fires the floor barrier with no sentinel present (review: model-drill).
- **gated (opt-in per workspace)** — the two lanes split:
  - **Upload lane (durability), every floor tick:** renew lease (D12), verify epoch, consume inbox (unchanged — inbound HITL adoption stays exactly today's behavior), scan, stage-diff, guarded uploads — but PUTs land **in place, as new object versions** (D7, rewritten on §8 Q2), and no manifest CAS runs. **The lane opens no HITL window** (review: crash-takeover, security-dos): the window exists to fence HITL out of the upload→CAS span (`inbox.rs:89-94` refuses gateway writes while a live window stands, cleared only by step 7's CAS, `barrier.rs:467`); a lane with no CAS that opened a 180 s-deadline window every 60 s would refuse HITL admission essentially forever between citations — and it protects nothing: with versioned staging a lane PUT creates a new version and destroys nothing HITL wrote, so there is no upload→CAS span to fence. Window open/clear belong exclusively to the citation lane. RPO for bytes stays at the floor. **Stage-diff base (review: ops-fleet):** the scan diffs against **baseline ∪ pending** — a path whose scan (size, mtime) matches its pending entry is *not* re-staged. Diffing against the baseline alone (which gated mode leaves un-advanced until citation) would re-PUT every staged-but-quiet file every tick: 50 quiet files × 60 ticks = 3,000 PUTs/hour vs today's 50, falsifying §7. Unit test: no re-stage of an unchanged staged file across N ticks. When a path *is* re-staged, the lane **deletes the superseded uncited version** (version-scoped DELETE, free; the version id is in the pending record) — uncited work holds at most one version per path plus crash remnants (review: gc-durability).
  - **Citation lane (visibility), at coherent points only:** **one CAS** installing the *entire* pending set — the versions already exist, so there is no copy phase — then GC, baseline rewrite, and version-scoped cleanup of superseded generations. Coherent points: **(i)** a publish sentinel; **(ii)** bounded quiescence — defined as **scan-to-scan stability**: no path's (size, mtime) changed between consecutive upload-lane ticks and nothing new appeared, for `quiesceBoundSecs` (review: gc-durability — the draft's "no scan diff vs baseline" definition could never fire once anything was pending, since pending paths stay classified-changed until citation: quiescence would have been dead code and every citation would ride the lag cap); **(iii)** the lag cap — `visibilityLagBoundSecs` elapsed since the last citation forces one even mid-change, stamped `boundary: "forced-lag-cap"`; **(iv)** the backlog cap — staged-uncited work exceeding `stagedBacklogCapObjects`/`stagedBacklogCapBytes` forces a citation, bounding the preStop drain to a sized backlog (review: ops-fleet, security-dos). (v — future, out of scope: fsync-derived boundaries; the enum reserves `"fsync"` as a source name only.) The report always says which source fired, and **the source is stamped bucket-visibly** — `cas_write` meta gains `flint-boundary-source` alongside `flint-gen` (review: ops-fleet): downstream consumers (checkout, sibling sync, HITL) can distinguish a declared-coherent citation from a forced possibly-torn one *from the bucket alone*, and the fleet can count chronic forced citations. Drill B10 asserts the stamp.
  - CRD validation: `gated` **requires** `visibilityLagBoundSecs` set — unbounded staleness is impossible by construction — plus the retention cross-validation and the versioning conformance probe in D8.

#### 2.4.2 Versioned staging — uncited generations are object versions (DECIDED — D7, rewritten on §8 Q2)

**§8 Q2 DECIDED (user, 2026-08-25): versioned staging is the v1 gated design; the CopyObject staging namespace is withdrawn** — not kept as a second engine. A fleet whose proxy fails the versioning conformance probe has `gated` **refused** and stays on the default `hybrid`, which needs no staging at all. Two staging engines would double the model tranche, the drill matrix and the crash matrix to buy a mode that is opt-in in the first place.

The copy design rested on one premise: `upload_one` PUTs to `files/<path>` guarded on the recognized baseline etag (`barrier.rs:564-638`), so a gated eager upload landing in place would **destroy** the cited object — checkout's If-Match fetch 412s and its S3-wins arm adopts the current mid-logical-change bytes (`checkout.rs:102-121`). **On a versioned bucket that premise is false.** An in-place PUT destroys nothing: the cited generation survives as a version, the manifest cites `(key, version_id, etag)`, and readers resolve the cited version exactly. The fleet-recommended posture is already versioning=Enabled (`s3.rs:418-433`).

What the switch **deletes** — machinery, not lines, and it is the bulk of the win: the `eager/` namespace; the per-citation `CopyObject` and its `UploadPartCopy` path for >5 GiB files; the citation-intent document and successor roll-forward; the stage-NotFound arm; the lifecycle-refresh re-PUT; superseded-stage deletes; `stage_key` in the pending record; and the transient copy-phase reader window. **A citation becomes one manifest CAS naming versions that already exist** — O(1) requests per boundary instead of O(dirty files), atomic by construction rather than by a recovery protocol.

- **Entry schema.** `LeanEntry` (`manifest.rs:25-36`) gains `version_id: Option<String>`. `None` = a legacy/unversioned entry ⇒ today's `get_whole(key, If-Match etag)` path verbatim; mixed manifests are normal during rollout and after any bucket-versioning change, so both forms are permanent reader cases. The etag stays and is still verified: **the version id addresses, the etag attests.**
- **Store surface — the cost the question understated.** `ObjectMeta` gains `version_id`: S3 already returns `x-amz-version-id` on PUT and `put_whole` **discards it today** (`s3.rs:178-187`), so citation needs no extra request. `ObjectStore` gains version-scoped `get_whole`/`head`/`delete` plus `list_versions`. Blast radius is small and *inside flint-store*: `ObjectMeta` is constructed at 9 sites, all in that crate, and the trait has exactly two implementors (`s3.rs:154`, `memory.rs:236`) — none in the hub. The real line item is that **the memory double must model version chains** (`memory.rs`, ~815 lines): the lean battery runs on `MemoryStore` with no AWS by deliberate crate design (`lean/sidecar/Cargo.toml:1-12`), so an unversioned double would leave the shipped design untested by every test that matters. Budget the double, not the sidecar.
- **Upload lane (gated), in place:** PUT to `files/<path>` with the guard chain unchanged (If-Match on the recognized baseline etag, AdoptOwn, park on foreign — the 412 policy inherited). The response's `version_id` lands in `pending[path]` alongside `base_version_id`, the version the baseline cited at staging time. No manifest CAS; the lane still opens **no HITL window** (§2.4.1's reasoning holds a fortiori — there is no upload→CAS span to fence, and a staged PUT now destroys nothing HITL wrote); stage-diff base stays baseline ∪ pending, so quiet staged files are not re-PUT.
- **Citation lane:** one CAS installing every pending entry with its recorded `version_id`. No copy phase ⇒ no half-boundary, no intent document, no roll-forward, and no interval in which a version-resolving reader can see boundary-new bytes under old citations. `Inv_BoundaryAtomic` holds by construction; the invariant and its split-CAS mutation stay in the model as the regression fence.
- **Citation-time re-validation survives, in versioned form (review: model-drill — the gated×sync amputation).** Pending records `base_version_id`; if `baseline[path].version_id ≠ pending[path].base_version_id` at citation, a HITL consume or sync landed after staging, and installing the staged version would **uncite** the foreign bytes. Same rule: re-scan the path, re-stage from the live tree if it still differs from baseline, else drop the pending entry with a conflict record naming the superseded generation. The damage class softens — under copy-staging the amputation *destroyed* the foreign object, here it only hides it and the version remains fetchable — but the rule and its TLC mutation stay.
- **The reader rule (DECIDED — D13, new — and the switch is incoherent without it).** A gated citation stamps the manifest `pinned_reads: true` (alongside `flint-boundary-source`). Under `pinned_reads`, flint's readers resolve **exclusively** by the cited `version_id` and never S3-wins-adopt the current version; HITL writes reach them through the ungated repair pass, i.e. within one floor (the HITL exemption below is unchanged). Without `pinned_reads` — cadence, hybrid, legacy manifests — `checkout.rs:102-121` keeps today's 412/S3-wins arm **verbatim**, so the shipped `hitl_upload_survives_two_barriers_without_sync` invariant is untouched in the default mode. Why it is load-bearing: the moment the gated lane stages a path, the cited etag stops matching current, so *every* gated checkout would 412 and S3-wins-adopt uncited mid-change bytes on *every* dirty path — the versioned design would leak its own staging into readers through exactly the arm the copy design existed to avoid.
- **Raw-key visibility — the trade, inverted from the question's framing (new).** Copy-staging kept uncited bytes out of `files/` entirely. Versioned staging makes them the **current version of the real key**: any reader that does not resolve through the manifest — an import tool, `aws s3 cp`, a foreign system pointed at the prefix, a human — now sees mid-logical-change bytes where it previously saw the last boundary. Flint's own readers all qualify as manifest-resolving under D13, so the guarantee holds where it is promised, but the promise is now **scoped to manifest-resolving readers** and says so in the CRD doc-comment and §3 residual 11. The torn-reader window closes structurally; a narrower, permanent raw-key exposure replaces it. It is modeled as a *required-reachable probe*, not as an invariant (§4) — the house rule against proving a guarantee by the attack's absence applies equally to proving a documented exposure by never generating it.
- **Straggler containment changes shape (review: crash-takeover).** Under copy-staging a deposed straggler's PUTs could not touch `files/` at all. Under versioned staging they land on real keys again — chaos C3's measured **7,591** post-deposal data PUTs would arrive as 7,591 uncited versions — but they **destroy nothing**: every cited version survives, a `pinned_reads` checkout never sees them, and cleanup is version GC. The honest claim moves from *"a straggler cannot touch cited keys"* to *"a straggler cannot destroy cited data; it can move the current-version pointer, which only raw-key readers follow."* Stronger for durability than the copy design, weaker for raw-key visibility. The shared-inbox TOCTOU (epoch-cell re-reads, cell-compared window ops, B12's oracle) is unchanged, and P5-at-the-proxy remains the fence.
- **Withheld deletes and GC.** Delete classifications are still withheld from the manifest until a citation pass, and GC still runs only after the CAS that uncites (`barrier.rs:412-441`, deletes-LAST model-pinned). Two simplifications: a delete marker can never destroy a cited version, and GC becomes **version-scoped** (D8).
- **The pending record** stays its own file `.flint-sync/pending.json` with the `clear_intent_keys` preservation test (`state.rs:180-212`) — minus `stage_key`, plus `version_id`/`base_version_id`. Write ordering is unchanged and now cheaper to reason about: PUT first, pending record second; a crash between them leaves an uncited version (version GC's side), never a pending entry naming a version that does not exist.
- **HITL exemption (unchanged, DECIDED):** inbox consume and the citation-repair pass are *not* gated — a HITL write is already a coherent, whole-object act by a foreign author. Repairs ride the next citation pass **or**, if none is due within one floor, trigger a repair-only citation (no local upserts). **Repair-only passes still withhold pending tombstones** (review: model-drill): installing withheld deletes without their paired staged creates would make a rename r→s reader-visible as r-gone/s-absent at an undeclared point. Pinned in product 4.

**The two safety properties, restated for versions (review: crash-takeover, gc-durability):**
1. **`Inv_ManifestKeysUnderFiles` gets easier and stays enforced.** With no `eager/` namespace there is no cite-in-place shortcut left to tempt anyone, but `manifest::cas_write` keeps refusing entries whose key lies outside `files/` — free insurance, mutation retained. The hazard it guarded has *moved*, not vanished: it is now "a lifecycle rule reaps a cited **version**", and D8 carries it.
2. **GC can never eat cited data — but the reaper set is versions now, and lifecycle can no longer be trusted with it.** Barrier GC addresses only what the installed manifest does not cite; model-pinned, unchanged. What changes is that the *backstop* now operates in the same namespace as cited data, at version granularity — the precise reason D8 originally chose a separate staging prefix. D8 answers it: exact reclamation is flint's job, the standing lifecycle rule is long, and a shorter fleet-wide noncurrent rule is a refusal condition rather than a warning.

#### 2.4.3 Version reclamation and the noncurrent backstop (DECIDED — D8, rewritten on §8 Q2)

Uncited generations are no longer objects in a prefix nothing reads; they are versions of the real keys. Reclamation splits accordingly.

**Exact reclamation is flint's job.** After each citation CAS, the barrier issues version-scoped `DeleteObjectVersion` (free) for every version of a touched `files/` key that neither the installed manifest nor `pending` names. Steady state ⇒ one version per key plus the live pending set — B21 asserts it. This is the reaper. Lifecycle is not.

**The backstop is dangerous in a way the eager-prefix rule was not — stated plainly, because it is the one place this design is worse.** D8's original argument for a separate staging prefix was that on `files/` an age-based rule *cannot distinguish cited from uncited*. Versioned staging reopens exactly that hole one level down, at version granularity, and with an inversion worth reading twice: gated staging makes the **cited** version *noncurrent* the moment a newer generation is staged. A `NoncurrentVersionExpiration` rule on `files/` therefore runs a clock against **live cited data** — and never against the newest uncited bytes, which are current and which no lifecycle rule can reach. The risk moved from "lose the last work" to "lose the pointer to the published state".

Consequences, all mandatory:
- **`noncurrentRetentionDays` defaults to 30**, operator-provisioned on `<prefix>/files/` with `ExpiredObjectDeleteMarker`, under `bootstrap_lifecycle`'s read-merge-append discipline (`s3.rs:763-840`) — `PutBucketLifecycleConfiguration` is full-replace and must never clobber the MPU-abort rule or user rules. Because exact reclamation already runs at every citation, a long standing retention costs ~nothing in steady state: it holds crash-window remnants only.
- **A shorter covering rule is a refusal, not a warning.** A9 *recommends* `NoncurrentVersionExpiration` fleet-wide (`s3.rs:418-433`), so a customer sitting at noncurrent-days=1 would arm the destroyer without touching flint at all. The operator reads the live lifecycle config; any rule whose scope covers `<prefix>/files/` with a shorter noncurrent expiration ⇒ `BoundaryModeAccepted=False`, gated refused, the offending rule Id named in the message. Re-checked on the operator cadence, never assumed stable. Leg B24.
- **The cross-validation survives verbatim in its new subject:** `noncurrentRetentionDays×86400 > K×(visibilityLagBoundSecs + floor_secs)`, K=2 — the longest a cited version can *legitimately* sit noncurrent is one staging window.
- **Versioning conformance is a probe, not an assumption:** versioning=Enabled, `x-amz-version-id` returned on PUT, GET/HEAD/DELETE by versionId, `ListObjectVersions` permitted. A project-scoped proxy that strips the version header degrades this design **silently** — pending entries would carry `None`, and citation would fall back to etag semantics on a key whose current version is uncited, which is precisely the torn view — so the probe refuses gated mode outright rather than degrading into it. Leg B24's control arm.
- **Sweep fallback** (proxies that cannot express lifecycle rules) keeps its shape: the operator's 1800 s pass issues version-scoped deletes for uncited versions older than the retention, driven off `orphans.json` with a `ListObjectVersions` fallback.

**§8 Q1's decision is honored; its mechanism retires with the copy design.** Q1 chose automatic protection with a hard 30-day bound over a runbook step, on the reasoning that a forgotten trigger must decay into a bounded cost rather than an eternal leak. Versioned staging **delivers that outcome with no machinery at all**: there is no staging prefix to watch and no rule to raise — the standing retention *is* the 30-day bound, it applies throughout DR without anything firing, and exact per-citation GC keeps its steady-state cost at ~0. `eagerOrphanAgeoutDays`, `drStagingAgeoutDays`, the two-pass debounce and the orphans-gated restore are all withdrawn. What survives from Q1: the 30-day number as the hard bound, the DR-signature **event + condition** (D9), and the runbook line for the operator-down window.

**The abandoned-mid-stage endgame (new — stated because it is worse than the copy design's).** A workspace abandoned with uncited work for longer than `noncurrentRetentionDays` loses its **cited** (noncurrent) version to the backstop while the uncited current version survives. The manifest then dangles, and checkout refuses rather than serving a hole (`checkout.rs:110-118` — correct, and loud). The bytes are not lost: `recover-staged` re-cites the surviving current version as a flagged boundary — a CAS, no data movement — so recovery rolls *forward* onto the newer work. Under copy-staging the same abandonment lost the uncited work and left checkout working. Neither is free: this one fails louder and recovers to more data, at the cost of a manual step before the workspace is usable. Verbatim in the CRD doc-comment; leg B23.

**Takeover + DR posture (DECIDED — D9, revised for versions) (review: gc-durability, ops-fleet).** A successor's claim path *surfaces* uncited-version candidates and never auto-adopts — auto-adoption would install a possibly-mid-logical-change set. The one prior exception, rolling a standing citation-intent forward, is gone with the intent document: a citation is now a single CAS that either happened or did not.
- **Surfacing stays durable and fleet-visible:** at claim time (and each citation) the sidecar writes `<prefix>/.flint/lean/orphans.json` — now `{path, version_id, size, stamps, staged_unix}` per candidate — which survives cluster loss, and the operator raises an event + condition when candidates exist with **no live lease** (the DR window is exactly when conflicts.jsonl and the CR no longer exist). `ListObjectVersions` diffed against the installed manifest is the fallback when orphans.json is missing or stale; it is the expensive path, which is why the durable summary is written eagerly.
- **`flint-sync recover-staged` stays a v1 deliverable and gets cheaper:** it re-cites named uncited versions as one flagged boundary (`boundary: "recovered"`, conflict records throughout) — **a manifest CAS with no data movement**, where the copy design had to copy or re-upload every path. Rationale unchanged: this fleet is pure-spot by standing directive, so pod replacement is the routine path and gated mode's RPO trade must be recoverable by an operator action rather than a rebuild. It is also the recovery for the dangling-citation endgame above.
- **DR statement, verbatim (also in the CRD doc-comment): uncited = invisible to every import, DR checkout, GitOps re-apply, and cross-cluster move** — with the versioned qualifier that keeps it true: *invisible to every **manifest-resolving** reader*; a raw `aws s3 cp` of the key sees the uncited bytes (§2.4.2). The operator explicitly designs for CR delete/recreate over the same data (`reconcile.rs:4-16`), and every one of those paths reads the cited manifest. The 30-day noncurrent retention applies throughout DR with nothing to trigger (D8); the runbook line — bucket-admin lengthens the rule by hand — remains for the operator-down window.

#### 2.4.4 preStop rule (DECIDED — D10, revised)

The SIGTERM arm's final drain barrier runs **fused and cite-everything in every mode**: all pending citations installed by CAS (the versions already exist — D7), all dirty files uploaded and cited, regardless of boundaries — then lease release. Revisions (review: crash-takeover, security-dos, gc-durability, ops-fleet — the draft's drain was unsized, un-retried, and settled nothing):

1. **The drain settles every owed ack before lease release:** a pending sentinel at SIGTERM is answered by the drain itself (`status: "ok"` after the fused install — the container-restart case where emptyDir and agent survive must not strand a waiting agent), or `status: "refused-fenced"` if the drain hits Fenced (the shipped path propagates Fenced with no ack and exits 0 — that branch now writes the refusal first).
2. **Bounded retry:** the shipped arm makes one attempt and releases the lease even on failure (`bin/flint_sync.rs:165-171` — `let _ = lease::release`). The drain retries the final barrier within the remaining grace budget before releasing; a transient store error no longer silently forfeits everything since the last boundary.
3. **Sized against grace:** §8 Q2 removes the per-*object* copy term the draft had to size against — installing pending citations is one CAS — leaving the parent plan's bytes×rate arithmetic (`flint-lean-plan.md:194-204`) over files dirtied since the last lane tick, a strictly smaller drain than the copy design's. The hazard it was sized against remains: the injected sidecar sets no `terminationGracePeriodSeconds` at all today, so it inherits the 30 s default; under a SIGTERM-ignoring agent, native-sidecar ordering burns the agent budget first. Rules: the webhook derives a grace bump from the configured caps × measured upload rate + slack (the startupProbe-derivation precedent, `inject.rs:40-54`); the CRD **refuses** gated mode when derived need exceeds configured grace (condition, same pattern as gated-requires-lag-bound); the **backlog-cap citation source (§2.4.1.iv) bounds the drain to a sized backlog by construction**; and the parent plan's early-drain hook runs a citation pass at deletionTimestamp observation so the final fused barrier handles only the last delta. On pure-spot fleets the ~2-minute reclaim cap is the routine ceiling — the arithmetic is run against it, and the gated CRD doc-comment states the spot-reclaim RPO consequence verbatim.
4. The cluster drill's A1 lossless-drain leg is the acceptance oracle; under gated mode the leg's precondition is *observed staged-uncited work*, and B11 gains a SIGKILL-mid-drain variant (recovery lands at the last boundary; orphans surfaced per D9) and a SIGTERM-ignoring-agent variant (the parent plan mandates that control for drain legs).

### 2.5 Layered doors and the capability marker

**Capability marker (DECIDED — D11, revised):** `.flint/capabilities.json`, written atomically **at every `run` startup — after claim succeeds, before the first poll** (review: crash-takeover — the draft pinned the write inside checkout completion, but the live-tree restart row returns at `marker_present()` (`checkout.rs:40-44`) without reaching it: an in-place sidecar image update would upgrade a fleet whose live workspaces never get the marker, leaving sentinels dead on exactly the pods the upgrade targeted). Also written during first checkout before the checkout-complete marker, so it exists the instant the agent may start.

```json
{ "protocol": 1, "verbs": ["publish", "sync", "remote-seq"], "boundary_mode": "hybrid",
  "state": "live",                       // "live" | "fenced" (D2)
  "sentinel_min_interval_secs": 5, "sentinel_hourly_budget": 60,
  "sidecar_version": "…",
  "boot": { "holder_id": "…", "boot_unix": 1756… } }
```

Absence ⇒ old sidecar ⇒ **sentinels are live ammunition** (they'd be scanned and published, §2.0); agents must check first. **Rollback direction (review: crash-takeover):** a rollback to an old sidecar over a live emptyDir leaves a *stale* marker claiming protocol 1 while the old sidecar scans `.flint/` — the hazard with the safety catch painted green. The `boot` stamp is the tell: the agent contract treats a marker whose boot stamp has not changed across an observed sidecar restart as suspect, and the runbook names the downgrade hazard loudly. B14 covers both directions (marker-absent old image; stale-marker-after-downgrade).

**UDS door (Phase 5, opt-in):** a Unix socket at `.flint-sync/ctl.sock` (state dir — outside the scan by the shipped exclusion) serving `POST /v1/boundary`, `POST /v1/sync`, `GET /v1/status`. Implementation: thin translation onto the *same* consume queue as the file sentinels — one code path, the socket is sugar with a synchronous response instead of ack-polling. Pod-internal only; no TCP listener; consistent with the no-new-remote-surface non-goal.

**Gateway verb (Phase 5, opt-in):** `POST /lean/v1/{workspace}/boundary` (bearer-authed like all verbs, `gateway.rs:12-38`) lets HITL/CI request a boundary from outside. **Transport revised (review: security-dos):** the draft routed this as a fake no-object `InboxEntry`, but `consume_inbox` HEADs `file_key(path)` for every entry and a no-object entry lands in the NotFound arm (`barrier.rs:80-90`) as a spurious `consume-object-missing` conflict — and special-casing the single most safety-critical function in the crate is worse. Instead the inbox **document** gains a dedicated `boundary_request: {requested_unix, requestor}` field, set by the gateway under the same CAS discipline, consumed by explicit logic at the sidecar's next inbox read (which happens every barrier/lane tick already — promptness is one floor, **zero added polling**, no per-tick GETs beyond today's). A consumed boundary request is treated as a consumed publish sentinel: same min-interval and hourly budget, same ack path (the ack lands in `.flint/publish.ack` and the report in gateway `/status`). Window/409 semantics untouched; per-request epoch validation does not apply (it claims no epoch).

**Sync requests are carried, never executed (DECIDED — D14, §8 Q4).** The inbox document gains a second field, `sync_request: {requested_unix, requestor}`, set under the same CAS discipline. The sidecar does **not** consume it as a sentinel and runs no sync on its account: it copies the values into `.flint/remote.seq` (§2.3) at the tick that reads the inbox, and stops. The asymmetry with `boundary_request` is deliberate and is about blast radius, not principle — a boundary publishes what is already on disk and touches no local file, whereas `sync` re-derives the tree against the current remote manifest and **deletes local files** for remotely-deleted paths (`sync.rs:122-130`, conflict-guarded only for dirty ones). Performing that on a remote's say-so would upgrade what a leaked gateway bearer can do from "publish, plus hand over these N named objects" to "rewrite and delete across a running agent's tree, at my timing, under a scope I choose". Carrying the request costs one field and leaves the choice where the design already puts it. Rate limiting: the field is idempotent state, not a queue — repeated sets before the agent acts collapse to the newest, so it needs no min-interval or budget of its own.

## 3. What v1 deliberately does NOT solve (residuals — stated, not hidden)

1. **mtime-granularity boundary evasion.** A write that changes bytes without changing size or coarse mtime within the same second can evade the scan diff (`scan.rs:73-75`) and therefore the boundary guarantee. Same residual as the barrier's; the ack does not upgrade it.
2. **No fsync-derived boundaries.** No interception is a non-goal; the boundary-source enum reserves the name only.
3. **Gated automatic-recovery RPO is the last boundary, not the floor.** Revised twice (review: gc-durability/ops-fleet; then §8 Q2): uncited bytes are durable as object versions, *named durably* in `orphans.json` (D9), and `recover-staged` re-cites them as a flagged boundary with a single CAS — but nothing automatic does; on pure-spot fleets pod replacement is routine and the CRD doc-comment says all of this verbatim, including: uncited = invisible to every import/DR/cross-cluster checkout.
4. **Deposed-straggler direct PUTs** remain the 7,591-class exposure until proxy-side P5 lands (chaos finding 2). Under versioned staging gated mode no longer moves those PUTs out of `files/` — it makes them non-destructive (uncited versions; cited data survives; `pinned_reads` readers never see them), which is a durability win and a raw-key-visibility loss (§2.4.2). The shared inbox cell keeps a TOCTOU exposure that cooperative re-reads shrink but cannot close (review: crash-takeover).
5. **No Prometheus scrape path until Phase 6, and it stays opt-in after** (§8 Q5 DECIDED — D15). Files + heartbeat echo + gateway JSON remain the authority for every operational decision; `/metrics` is additive fleet observability, off by default, and a workspace with it disabled is fully operable.
6. **Sentinel authorship is per-workspace, not per-agent — and acks are forgeable in-pod** (review: security-dos). Multiple processes share one sentinel pair; nonces + cumulative covered-nonce acks are the disambiguation. The ack is advisory (§1.2); the authoritative durability read is remote.
7. **`.flint/publish` has no scope** — whole-workspace boundaries only.
8. **UDS/gateway doors are optional and late** (Phase 5); the file protocol is the only guaranteed interface.
9. **Legacy `files/.flint/...` citations are frozen, not migrated** (D0.2) — a warning record, no auto-rewrite.
10. **Versioning conformance of the deployment proxy is a gate, not an assumption** (§5 Phase 3 gate; §8 Q2 DECIDED): versioning=Enabled, `x-amz-version-id` on PUT, GET/HEAD/DELETE by versionId, `ListObjectVersions`. A stripped version header would degrade gated mode into the torn view it exists to prevent, so the probe refuses rather than degrades — re-probed on the operator cadence, never assumed stable.
11. **Raw-key readers see uncited bytes** (§8 Q2's inverted trade — replaces the copy-phase transient window, which versioned staging closes structurally). Uncited generations are the *current version* of real `files/` keys, so a reader that does not resolve through the manifest — an import tool, `aws s3 cp`, a foreign system pointed at the prefix, a human — observes mid-logical-change bytes. Flint's own readers are manifest-resolving under D13; the coherence promise is scoped to them, in the CRD doc-comment and here. Permanent and narrower than the window it replaces, but it never closes on its own, and it is required-reachable in the model rather than assumed away.
12. **Sentinel request amplification is bounded, not eliminated** (review: security-dos). An agent at the budget ceiling still costs more requests than cadence-only; §7 prices the ceiling, per workspace and per project proxy.

## 4. Formal model tranche 3 (rewritten — review: model-drill)

Extend `lean/formal/LeanSubtree.tla` by the tranche-2 pattern: new CONSTANTS default-FALSE in every existing cfg so tranche-1/2 state spaces are preserved by construction (`LeanSubtree.tla:40-64`, `gen-cfgs.sh` emit; bump `check.sh`'s `$PASS` and the README count). New constants: `BoundaryEnabled`, `GatedCitation`, `EagerStaging`, `SyncScope`.

**Substrate — the draft's "no new substrate" claim was false and is retracted (review: model-drill, critical); §8 Q2 then changed what the new substrate must be.** In the shipped spec, `objects[p]` *is* `files/<path>`: GCDelete deletes it, `Inv_NoDangling` checks manifest→objects, CheckoutB reads it. A single-slot `objects[p]` cannot express versioned staging at all — modeling a gated upload as an `objects[p]` advance would model an in-place *overwrite*, i.e. the destructive design versioning exists to avoid, which is the thrice-paid "the abstraction was the bug" class committed in the planning document. Real substrate additions:

- `versions[p]` — an ordered set of version ids per path with the bytes/etag each carries, plus `current[p]` (the newest live version). `Upload` appends and advances `current`; nothing overwrites. The per-uuid collapse of the copy design is gone; what is collapsed instead is version *content* (a version is its generation number) — stated in the abstraction ledger.
- Manifest entries cite `(p, version)`; `Inv_NoDangling` strengthens to **`Inv_CitedVersionLives`** — no manifest entry names a version that has been reaped. Required mutation: the noncurrent backstop expires a cited-but-noncurrent version (D8's inverted hazard) — must fire.
- `pending` — sidecar state surviving `Restart`, dying with pod-replacement `CrashPod`, carrying `base_version` per path (the D7 re-validation guard). `staged`, `Copy` and the `citation_intent` ghost are **deleted** from the tranche with the copy design.
- `sentinel` token + ack ghost (`gh`) for product 1.
- Two reader actions, not one (review: model-drill — the shipped model abstracts checkout's 412/S3-wins arm, safe at one-tick payloads, unsafe when the tranche's point is boundary-sized payloads). **`PinnedReader`** resolves the cited version (D13) — invariant: it never materializes post-boundary bytes under pre-boundary citations, and with no copy phase this must hold with no recovery path involved. **`RawReader`** reads `current[p]` — it carries no invariant; instead `ProbeRawReaderSeesUncited` is REQUIRED-reachable, so the documented exposure (§3 residual 11) is proven present rather than assumed away, and a future design that quietly closes it must fail the probe and force the doc to change.
- Abstraction ledger entries for everything still collapsed (version content → generation number; ack file → ghost; budget/min-interval → out of the safety gate).

## 7. Economics (rebuilt in request units — review: ops-fleet, security-dos)

Baseline prices (S3 standard): PUT/COPY/CAS $0.005/1k, HEAD/GET $0.0004/1k; intra-region copy moves no billable bandwidth; DELETEs and lifecycle expirations are free.

**The real idle tick (correcting the draft):** 4 requests, not 1 HEAD — lease renew (a CAS write, **PUT-priced**, `flint_sync.rs:154`), `verify_not_deposed`'s epoch read, `consume_inbox`'s inbox GET (runs *before* the fast path, `barrier.rs:190-193`), and the manifest HEAD. Fleet baseline at 3,000 workspaces / 60 s floor: 50 PUT/s + 150 GET/s ≈ **$27/day** — that is *today's* cost, unchanged by this plan, but the draft's "$0.06/hour, 1 HEAD" figure was ~19× under (renewals are PUT-priced) and B8's old oracle would have failed against a correct sidecar on day one.

**This plan's default-posture delta:** D12's 30 s heartbeat renewal adds +1 PUT/min/workspace when floor > 30 s ⇒ +50 PUT/s fleet-wide ≈ **+$21.6/day at 3,000 workspaces** — the one deliberate default increase, bought for takeover-safety (§2.1a), stated here and in the D12 doc-comment. remote.seq, the sentinel poll (2 local lstats/s), and the capability marker add **zero** bucket requests.

**Hybrid (default):** published *bytes* unchanged — a sentinel barrier publishes the same dirty set earlier. Requests: each forced barrier ≈ 3 PUT-priced (window CAS, manifest CAS, renew) + 3 GET-priced. Uncapped worst case at min-interval 5 s would be 17,280 forced barriers/day ≈ $0.28/day/workspace control-plane **plus** the real cost the draft missed: re-PUTs of hot small files at 12× cadence, agent-controlled (a 1-byte file dirtied in a loop re-PUTs every 5 s — request-priced identically to a large PUT). `sentinelHourlyBudget=60` caps sustained forced barriers at ≈ cadence-equivalent (≤1,440/day): sustained worst case ≈ 2× today's barrier count per storming workspace ≈ +$0.03/day/workspace control-plane. **The re-PUT term is bounded by D3.1's work metering, not left open:** sentinel-driven published bytes cannot exceed `budget × whole_put_max` = 3.84 GiB/hour/workspace at defaults, regardless of dirty-set size, and a workspace that hits the cap falls back to cadence — today's bytes exactly. The one term the meter deliberately leaves free is the *no-diff* honor (one HEAD, no data): min-interval bounds it at 720/hour/workspace, which is HEAD-priced (~$0.0003/hour) but is a fleet-correlated proxy-QPS term at 3,000 workspaces — sized alongside the barrier rate above. Fleet-correlated exposure (review: ops-fleet): the budget is per-workspace; one framework bug touching `publish` in a loop *everywhere* multiplies by fleet size against the shared project proxy — per-project proxies should be sized for `workspaces × (budget+floor)/hour` barrier rate, and the D8/operator posture section carries that sizing note. Typical agent behavior (a boundary per logical op, minutes apart) is noise.

**Gated (re-priced on §8 Q2 — this is where the versioned bet pays).** Bytes at cadence, unchanged (the lane diffs against baseline ∪ pending — §2.4.1 — so per-file PUT count per tick cannot exceed today's; hot >64 MiB files additionally pay per `perFilePublishCooldownSecs` only if that opt-in knob is set). **The per-citation COPY term is gone**: a citation is one manifest CAS naming versions that already exist, so citation cost is O(1) per boundary instead of O(dirty files), and >5 GiB files no longer take an `UploadPartCopy` path at citation at all.

The copy design's bill, kept here as the thing not being paid: 50 dirty files cited every 5 min = 14,400 COPY/day ≈ $0.07/day/workspace; at the 3,000-workspace fleet example, 43.2M COPY/day ≈ **$216/day ≈ $6.5k/month** plus ~500 sustained req/s of pure copy traffic through the project proxies. Versioned staging retires all of it, and with it the "gated adoption at scale is a proxy-QPS sizing exercise" caveat — gated citation traffic is now one CAS per boundary per workspace, the same order as the renewals already priced above.

What replaces it is **storage, not requests**: uncited versions (at most one generation per dirty path, deleted by version GC at the next citation) plus crash-window remnants held until `noncurrentRetentionDays`. That is the same storage the copy design held as staged objects — minus the interval where a path existed *twice*, staged and copied. Version-scoped DELETEs are free. The remaining request adds over cadence are D3's sentinel budget and the citation CASes themselves.

**What the design refuses to spend:** no per-agent polling against the bucket (remote.seq exists so N agents cost 0 requests, not N×HEAD), no manifest GETs for news (HEAD stamp only), no added inbox polling for the gateway verb (rides the existing per-barrier inbox GET), no bucket-wide LISTs (staging list is prefix-scoped, claim-time and operator-cadence only), no unbounded forced-barrier rate (budget).

## 7b. Axis impact — the no-regression argument

**Under defaults (hybrid, sentinels present but unused unless touched):**

- **Consistency — improved, never traded.** The merge/park/conflict machinery is untouched (`manifest.rs:108-146`, upload 412 policy, sync scan-first rules). Hybrid adds coherent points to today's cadence points and removes none; citation timing never lags today's (B16 is the regression proof). D0's delete-exemption removes a latent upgrade data-loss hazard. D4 is designed *specifically* so a new verb cannot lose out-of-scope foreign flow — and is modeled before code.
- **Performance — zero *bucket* cost unused except the priced D12 heartbeat (review: ops-fleet — the draft's "zero-cost, 1-HEAD tick" claim was wrong at the baseline).** Scan skips `.flint/` (marginally cheaper); 2 lstats/s poll; remote.seq and marker are local renames; the delta vs today is exactly +1 renew PUT/min/workspace (§7), stated rather than hidden. B8 is the measured proof obligation, against the real 4-request control shape.
- **Hot loops — explicitly defended, because this is the sub-axis the plan could most easily have cost (D3.1).** Lean maxes that axis today for a structural reason: a tight local loop writes at local-disk speed and its republish is *coalesced by cadence*. Sentinels un-coalesce it on demand, so an unmetered budget would have let a storming agent multiply upload bytes for a hot large file while staying green. The work-metered budget bounds sentinel-driven bytes at `budget × whole_put_max`/hour independent of dirty-set size, degrades to exactly today's cadence behavior at the cap, and leaves no-diff honors free — with B25 as the two-armed proof (large-file storm throttles, small-file storm does not). What the plan does *not* claim: it does not improve hot loops, and the cadence-driven amplification for hot >64 MiB files (the parent plan's 2.9 TiB/day pathology) is untouched here — that is the flush-profile tranche's cooldown, §8 Q6.
- **Security — surface unchanged by default; one class narrowed; two hazards closed that the verbs would have weaponized (review: security-dos).** No new remote surface for the app (file protocol only by default; UDS pod-internal opt-in; gateway verb bearer-authed and off by default). D15's `/metrics` is the one listener that binds the pod network, and it is off by default, carries no path or identity labels, and ships with a monitoring-namespace-only NetworkPolicy — the exposure is counts and durations for a workspace whose name the reader already had to know. Sentinels are writable only by containers already sharing the mount — and the ack is documented advisory for the same reason (§1.2). The sync sentinel forced the pre-existing `write_file_atomic` symlink-traversal exposure to be closed (Phase 2) rather than made agent-triggerable. Sentinel type-checks close the FIFO/dir DoS. In gated mode the deposed-straggler blast radius changes shape rather than shrinking (§8 Q2): its PUTs still land on real `files/` keys, but they **destroy nothing** — cited versions survive, `pinned_reads` readers never see them, and cleanup is a version GC, with recovery a re-cite CAS. Durability exposure drops; raw-key visibility exposure is the price (§3 residual 11). The inbox-cell TOCTOU is named (§2.4.2), D14 deliberately declines to widen the gateway bearer from publishing to rewriting a live tree, and P5-at-the-proxy remains the plan of record for the rest.
- **Day-2 operations — additive, with the mixed-version and propagation holes closed (review: ops-fleet).** All knobs default to today's behavior (the draft's cooldown default violated this and was corrected to 0); conditions are new (none existed); the capability marker + heartbeat echo make **both** mixed-fleet directions (agent↔sidecar, operator↔sidecar) detectable instead of silently hazardous; knob propagation semantics (pod-recreate-only) are stated; the CRD-in-operator-binary delivery and rollback schema-reversion hazard are named; Phase 3 ships a pageable minimum (withheld_reason, heartbeat lag echo, `flint-sync status`) so "why is the manifest not advancing" is answerable before Phase 6.
- **Availability — degraded-to-today, never worse.** Sentinel consumption failure degrades to cadence publishing — hybrid's OR guarantees the manifest still advances on the floor, on an interval timer that no arm can starve (D3/D12 — the draft's select structure would have starved renewal and *deposed the writer*; closed). remote.seq fails stale-never-wrong with a heartbeated `updated_unix` as the tell. Fenced sidecars now answer their agents (refused acks) instead of stranding them. The gateway/proxy failure split (chaos C8/C12) is unmoved. The flock, lease-claim, takeover, and rotation protocols are untouched; renewal cadence tightens (safer, priced).
- **Multicluster — unmoved.** One-writer-per-subtree intact; boundaries are properties of the single writer's manifest sequence; remote.seq is per-pod local; the boundary-source stamp travels in manifest meta all clusters already read; nothing else crosses cluster boundaries that didn't already.

**What each opt-in trades (stated here and in the CRD doc-comments):**

- **`boundaryMode: gated`** trades, re-stated on §8 Q2: (1) automatic-recovery RPO — a replaced pod recovers to the last *boundary*; on pure-spot fleets replacement is **routine**, which is why `recover-staged` ships in v1 (now a re-cite CAS) and the doc-comment states the spot-reclaim consequence and the DR corollary verbatim (review: ops-fleet, gc-durability); (2) **raw-key visibility** — uncited generations are the current version of real keys, so non-manifest-resolving readers see mid-logical-change bytes (§3 residual 11); (3) storage for uncited versions + crash remnants until `noncurrentRetentionDays`; (4) a **harder** proxy conformance bar (versioning + version-id preservation + version-scoped ops), refused visibly via condition, never degraded into; (5) the noncurrent backstop's inverted hazard and its abandoned-mid-stage endgame (D8). It buys: coherent views at every citation *for manifest-resolving readers*, with no copy phase and no torn-reader window at all; O(1) citation cost; non-destructive stragglers; and a bucket-readable coherence stamp. What it no longer trades away: the per-citation COPY bill (§7), the citation-intent/roll-forward machinery, and the copy-phase window.
- **Low `sentinelMinIntervalSecs` / high `sentinelHourlyBudget`** trade S3 request cost for boundary latency — bounded and priced in §7, per-workspace and per-proxy.
- **`perFilePublishCooldownSecs` > 0** trades >64 MiB-file RPO (floor → cooldown) for PUT cost — off by default (review: ops-fleet).
- **UDS door** trades one pod-internal listener for synchronous responses.
- **Gateway boundary verb** trades one more bearer-authed verb for HITL-initiated boundaries.
- **`cadence` mode** pins the exact pre-boundary behavior (the escape hatch) — reachable for new pods only; switching a live gated workspace manufactures orphans, which `recover-staged` exists to re-install.

## 8. Open questions for the user

**All six DECIDED (user, 2026-08-25).** Kept in question form as the decision record — each entry states what was chosen and, where the question's own framing was wrong, what the correction was.

1. **DR ageout posture (D8/D9) — DECIDED (user, 2026-08-25): (b), raise-not-suspend, 30-day limit.** As decided against the copy design: on the DR signature (staging prefix non-empty + no live lease) the operator **raises** that workspace's staging rule to `drStagingAgeoutDays=30` instead of suspending it, and restores the standing age only once the lease is live *and* no orphan candidates remain surfaced. The raise-over-suspend choice is about which failure mode you inherit when the automation fires and is then forgotten: a bounded 30-day storage cost, rather than suspend's eternal leak or runbook-only's silent loss inside the recovery window. **Superseded in mechanism by Q2, honored in outcome:** versioned staging leaves no staging prefix to watch and no rule to raise — the standing `noncurrentRetentionDays` *is* the 30-day bound, applying through DR with nothing to trigger, so the raise, the debounce and the restore gate are withdrawn along with `eagerOrphanAgeoutDays`/`drStagingAgeoutDays` (D8). What survives: the 30-day bound, the DR-signature event + condition (D9), and the runbook line for the operator-down window.
2. **CopyObject-staging vs versioned-bucket staging — DECIDED (user, 2026-08-25): versioned staging, priced now.** D7/D8/D9 are rewritten to it and the copy design is withdrawn rather than kept as a second engine (a proxy that fails the versioning probe gets `gated` refused and keeps the default `hybrid`). Priced: the per-citation COPY bill goes to zero and citation becomes O(1); the torn-reader window closes structurally, taking the citation-intent document, the roll-forward protocol, the stage-NotFound arm and the `eager/` namespace with it. Bought at: a `LeanEntry`/`ObjectMeta` schema change plus version-scoped `ObjectStore` methods and **version chains in the `MemoryStore` double** (the real code line item, since the battery runs on it); the D13 reader rule, without which gated checkouts would S3-wins-adopt their own staged bytes; a permanent **raw-key visibility** exposure replacing the transient one (§3 residual 11); and the inverted lifecycle hazard — the noncurrent backstop now runs a clock against *cited* versions, so a shorter fleet-wide noncurrent rule is a refusal condition (D8, leg B24). Two follow-ons for you, both defaulted and both cheap to reverse: **(a)** the raw-key exposure is accepted rather than papered over (papering over it *is* the copy design); **(b)** `pinned_reads` is set only by gated citations, so cadence/hybrid keep today's S3-wins arm byte-for-byte.
3. **Defaults check — DECIDED (user, 2026-08-25): confirmed as the v1 shipping defaults, "for now".** `sentinelMinIntervalSecs=5`, `sentinelHourlyBudget=60`, `quiesceBoundSecs=30`, `stagedBacklogCapObjects=5000`/`2 GiB`, `noncurrentRetentionDays=30` (carries §8 Q1's bound), `perFilePublishCooldownSecs=0` (the 300 s draft default was a regression and is gone). Two things that make "for now" cheap to act on:

   **Changing a default later is an operator-image change, and it reaches new pods only** (§2.6 propagation semantics — sidecar config is env-stamped by the webhook at pod creation, `inject.rs:108-131`, and the CRD ships compiled into the operator, `flint_lean_operator.rs:129-148`). A default revision therefore lands like any other rollout: operator first, then pod recreation per workspace. Per-workspace overrides need neither.

   **Each default gets a named tell, so "for now" ends on evidence rather than on someone remembering** — all off gauges and stamps Phase 3 already ships, no new machinery:
   - `sentinelMinIntervalSecs`/`sentinelHourlyBudget` — `sentinel_budget_remaining` (in D3.1 **units**, not calls) reaching 0 outside a storm test, or acks routinely stamped `sentinel-deferred`, means a normal agent cadence is being rate-limited rather than an abusive one (B3 measures the coalescing shape, B25 the metering). A workspace exhausting on *unit* count with few honors is publishing large dirty sets per boundary — the signal to look at the flush-profile cooldown (§8 Q6), not to raise the budget.
   - `quiesceBoundSecs=30` — chronic `forced-lag-cap` in the manifest's boundary-source stamp with `forced_citation_count` climbing while quiescence rarely fires: 30 s is too tight for the real write rhythm, and every citation is riding the cap (B20's failure shape, at fleet scale).
   - `stagedBacklogCapObjects/Bytes` — backlog-cap becoming the *dominant* citation source, or preStop drains measuring close to derived grace (D10), means the cap is doing the pacing instead of bounding the drain.
   - `noncurrentRetentionDays=30` — `cited_noncurrent_age_max_secs` should sit ≪ retention in steady state (exact GC reclaims at every citation); it approaching the retention means workspaces are dying mid-stage often enough that the backstop, not GC, is the reaper.
   - `perFilePublishCooldownSecs=0` — per-workspace request counts dominated by re-PUTs of the same >64 MiB file; the knob exists for exactly that fleet and stays off until one shows up.

   **One honest note on a check that no longer binds where it reads like it does:** the retention cross-validation `noncurrentRetentionDays×86400 > 2×(visibilityLagBoundSecs + floor)` cannot fire at the 30-day default until a lag bound exceeds ~15 days, which no fleet will set. It is not dead — it binds when someone *lowers* retention (a 1-day retention against an hour-scale lag bound is refused, which is the case worth catching) — but it is a guard on the retention knob, not on the lag bound, and D8 should be read that way.
4. **Gateway verb scope (Phase 5) — DECIDED (user, 2026-08-25): boundary performed, sync *requested* (D14).** The gateway gets both `boundary_request` (consumed as a publish sentinel, as drafted) and `sync_request` (copied into `.flint/remote.seq` as advisory news; the sidecar mutates nothing on receipt). The agent pulls at its own safe point and gets the normal ack.

   **The draft's stated rationale was wrong and is corrected.** "Sync-by-inbox mutates the live tree on a remote's say-so, violating the agent-chosen safe point" does not distinguish sync from what already ships: `consume_inbox` writes foreign bytes into the live tree at *every* barrier and lane tick (`write_file_atomic`, `barrier.rs:139`) for any path that is not locally dirty — the D7 HITL exemption, deliberate and shipped. The real distinction is **blast radius**: the inbox applies a bounded set of objects explicitly handed to this workspace and only ever writes, while `sync` re-derives the whole tree against the current remote manifest and **removes local files** for remotely-deleted paths (`sync.rs:128`). Sync is durability-safe (local dirt wins, conflicts recorded — B6) and coherence-unsafe (the agent's inputs change and vanish mid-flight — the reader-side failure gated mode exists to prevent).

   **Why the advisory field is not just a no-op:** the two delivery paths that already exist cover most of the need — targeted HITL delivery lands via the inbox within one floor with no verb at all (B19), and `observed_seq > integrated_seq` already tells a watching agent there is news. What was missing is *promptness with attribution* for "please pull now", which one ticker field buys without handing a remote party scope over someone else's filesystem. For a genuinely stuck agent the escalation is pod recreation (checkout re-materializes from the cited manifest — coherent by construction), not a forced rewrite.
5. **Metrics plumbing (Phase 6) — DECIDED (user, 2026-08-25): a `/metrics` listener on the sidecar (D15).** Prometheus exposition from `flint-sync`, **opt-in per workspace**, additive to everything already shipping.

   **One correction to the question's own framing, because it decides the bind address.** "Localhost, pod-internal" and "fleet-scrapeable" are mutually exclusive: containers in a pod share a network namespace, so `127.0.0.1` is reachable from the agent container and nothing else, while Prometheus scrapes from another pod via the **pod IP**. A loopback-only listener would be unscrapeable, and the only way to scrape it would be a collector container per workspace — 3,000 extra containers at fleet scale. So the listener binds the pod network (`0.0.0.0:<port>`, default off), and the exposure is bounded by NetworkPolicy rather than by the bind address.

   Rules, each earned by a hazard this fleet has already met:
   - **It must never kill what it measures.** A failed bind — the agent container already owns the port, since the netns is shared — logs, sets a condition, and the sidecar continues. A metrics listener that can crashloop a workspace is a strictly worse trade than no metrics. Default port is high and unusual, and per-workspace configurable for the collision case.
   - **A scrape costs zero bucket requests.** Exposition renders from the same in-memory struct `gauges.json` serializes — never a HEAD, never a LIST. This is the "instrument reports on itself" class the runas campaign paid for five times, and here it would also make B8's zero-added-cost oracle intermittently red and blame the sidecar for it.
   - **Parity with `gauges.json` is a test, not a convention:** every field in the JSON has exactly one metric with the same value at the same tick. Two renderers over one struct cannot drift; two computations would.
   - **Cardinality is fixed by construction:** labels are `{workspace, namespace}` and nothing else — never a path, never a file, and never `sync_requested_by` (D14's requestor identity stays in the ticker and the JSON). ~10 series/workspace ⇒ ~30k series at the 3,000-workspace fleet. A gate test asserts the label-key set is exactly that pair; without it, one per-path metric is a fleet-wide cardinality incident.
   - **Ingress is closed by default:** the chart ships an opt-in NetworkPolicy admitting only the monitoring namespace (kindnet enforces NetworkPolicy since kind v0.32.0, so the e2e can actually prove it rather than assert it).
   - **Discovery:** the webhook stamps `prometheus.io/{scrape,port,path}` annotations when metrics are enabled; a `PodMonitor` ships behind a chart flag in the `gateway.enabled=false` style, since it needs the Prometheus Operator CRDs to exist.
   - **No new dependency:** the crate already carries `warp` 0.3 for the gateway binary (`bin/flint_lean_gateway.rs:96`); the sidecar reuses it, paying binary size rather than a new supply-chain edge.
   - **Nothing operational depends on the scrape.** The heartbeat echo stays the operator's authority for lag (a condition and a printer column that work with no metrics stack and survive a Prometheus outage), and `gauges.json` stays agent- and exec-visible. An old sidecar image with metrics enabled in the CR simply has no listener: the target goes down, and no decision path notices.
6. **Cooldown home — DECIDED (user, 2026-08-25): referenced, not implemented here.** `perFilePublishCooldownSecs` belongs to the lean plan's flush-profile tranche (`flint-lean-plan.md:200-204`, §6's amplification pathology — a 2 GiB hot file re-uploads whole per barrier, ≈2.9 TiB/day at 60 s cadence, because lean has no delta upload: `upload_one` sends every byte, multipart above `WHOLE_PUT_MAX`=64 MiB, `lib.rs:69`/`barrier.rs:471-511,590`). This plan takes a dependency, not the implementation — Phase 3 is already carrying the flint-store version surface.

   **What this plan keeps and does not hand off: the D1 corollary.** A sentinel-honored barrier **ignores the cooldown** — contents are never thinned — or the ack lies: "boundary complete" while a 2 GiB file was withheld is exactly the guarantee the verbs exist to provide. Recorded in three places on purpose, because a constraint written only in a plan that does not implement it is how it gets lost: here; as an acceptance requirement *on* the flush-profile tranche (its cooldown must ship with a test that a sentinel-honored barrier publishes an over-threshold file inside its cooldown window, red against a naive implementation); and in the knob's own CRD doc-comment, which is the copy that travels with the code.

   Nothing in the boundary design depends on the knob otherwise: it ships default-0, Q3 names the tell that should turn it on (per-workspace request counts dominated by re-PUTs of one >64 MiB file), and the parent plan's v2 lever — `UploadPartCopy` of unchanged ranges — would make it largely moot for that file class.

### 10.1b The Phase-3 completion tranche — what it found

Thirteen more legs (52 → **65**) and **sixteen more mutations**, each
applied to the shipped code, observed red, and reverted. Up to this
point `gated.rs` was reachable only from tests: `boundaryMode: gated`
parsed, validated, refused itself without a lag bound — and then ran the
fused cadence barrier like every other mode. It was the "knobs that
exist and do NOTHING" class, one wiring commit from being shipped that
way.

Four defects, none of them the wiring itself:

1. **The versioning conformance probe could wedge gated mode
   permanently.** It writes its object `If-None-Match: *` and cleans up
   at the end; a crash — or one failed cleanup DELETE, which the code
   discarded with `let _` — leaves the object behind, and every
   subsequent probe then 412s on its *first* write and refuses. A
   transient error would have taken a gated workspace down until a human
   deleted an object by hand. The probe now sweeps its own leftovers,
   and sweeps again at the end so a partial cleanup cannot wedge the
   next run either.
2. **The preStop drain moved data in gated mode.** Running the fused
   barrier at SIGTERM re-uploads bytes the lane already staged, at the
   one moment there is no time for it — and D10's grace sizing is
   explicitly premised on "installing pending citations is one CAS". It
   also left the final boundary of the workspace's life carrying neither
   the `drain` stamp nor `pinned_reads`. Isolated by mutation: with the
   stamp assertions removed, the version-identity assertion *still*
   fired, so the re-upload was real and not a bookkeeping difference.
3. **`checkout` never wrote the capability marker**, though D11 says it
   must, before the completion marker, so it exists the instant the
   agent may start. `run` wrote it either side of checkout, so the gap
   was invisible there and total for the standalone `checkout`
   subcommand. Correcting it broke an existing test's *fixture* — which
   had reached "no marker yet" by relying on the bug — so the fixture
   now constructs that state as what it actually is: a live tree checked
   out by an old binary, with a new image dropped in place.
4. **`CitationSource::Recovered` was defined and never constructed**,
   because `recover-staged` did not exist. It does now, and the source
   is what stamps its boundary.

**Two design calls made here, stated rather than buried.**

- **The news ticker moves at citation points in gated mode.** D5's rule
  is that the ticker never issues a request of its own — it rides the
  barrier's existing manifest HEAD. The upload lane has no such HEAD, so
  keeping ticker freshness at floor cadence under gated would cost one
  added HEAD per tick per workspace (60/hour), which is the same order
  as the entire sentinel budget. Inbound news therefore refreshes at
  coherent points, which is consistent with what the mode means; the
  cost is that an agent learns of a sibling's publish up to
  `visibilityLagBoundSecs` later than it would in hybrid.
- **`withheld_reason` names `version-probe-failed`, not the plan's
  `copy-probe-failed`.** §8 Q2 withdrew the CopyObject staging engine
  entirely, so the draft's value named machinery that no longer exists.
- **The operator-facing heartbeat echo is deferred to Phase 4**, on
  purpose. The plan's argument for it is that it is *free* — it rides
  the lease-heartbeat cell the sidecar already renews. But
  `EpochState`/`EpochLease` carry no free-form payload, so it is free
  only after a shared `flint-store` schema change that also touches the
  hub's arbitration path — and the only consumer is the operator's
  `BoundaryModeActive` condition, which does not exist yet. A separate
  heartbeat object would cost ~120 PUTs/hour/workspace, which is not
  free and is precisely the "instrument reports on itself" tax. It
  lands with the operator, or not at all. The *local* half of OF-6 —
  "why is the manifest not advancing", answerable by `cat` inside the
  pod — is shipped.

### 10.2 Formal model — tranche 3, product 4 (done)

`SyncScope`/`ScopedInstBase` join `LeanSubtree.tla` behind constants that
are FALSE in every pre-existing cfg, so tranche-1/2 state spaces are
preserved by construction. Three runs added (24 → **27**):
`LeanScopedSyncHolds` (strict), `LeanScopedSyncWholeBase` (the
whole-base mutation, must violate `Inv_NoForeignLost`), and
`LeanProbeScopedDeferral` (action-written non-vacuity ghost).

**The model found the same trap the Rust test fell into, independently.**
The first cfg ran the mutation green — because the D4 loss needs an
out-of-scope change living in the MANIFEST, and an inbox-overlaid change
survives a wholesale `instBase` advance untouched. In this design the
only legitimate foreign manifest installer is a takeover successor, so
the runs need `AllowStall` and a second barrier; without them the hazard
is unreachable and the mutation checks a state space that never
contained the bug. Recorded in `lean/formal/README.md`.

**Affordability was piloted before the budget was locked in**, per §4's
obligation: at `MaxGen=3`/`MaxHitl=1` the strict run passed 30M states
without terminating; at `MaxGen=2`/`MaxHitl=0` it completes in ~9 s
**and both the mutation and the probe still fire**, so the strict run is
not checking a smaller world than the bug lives in. Whole gate: ~75 s.

Products 1 (boundary × barrier × inbox, with the deposal arm), 2 (gated
citation × version GC × the noncurrent backstop) and 3 (straggler)
remain unmodelled. Priority order and the reasoning are in §10.3.

### 10.3 What to model next, and what not to

- **Product 1 — do it.** The ack/fence/crash matrix is where the plan
  retracted its own per-crash prescriptions, and `Inv_NoNonceOrphan`
  under coalesce + crash + restart is an interleaving property that unit
  tests sample rather than search. `settle_pending_at_startup` is
  currently justified by one ordering out of many.
- **Product 2 — do it, with the pilot first.** `Inv_CitedVersionLives`
  is not hypothetical: it was violated in shipped code this session
  (§10.1 defect 1), and the tests caught it only because assertions
  happened to be written in the right places. It needs the
  `versions[p]`/`current[p]` substrate and `MaxVersionsPerPath`, and the
  product-4 experience says budget the pilot generously.
- **Product 3 — defer.** Its real content is a required-reachable probe
  (a deposed writer's PUT lands and becomes `current[p]`), the fence
  that would make it an invariant is P5 at the proxy, which is not
  built, and drill leg B12 covers the shape better than a model would.
