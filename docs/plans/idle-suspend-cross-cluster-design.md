# Recommendation: publish the connection witness, bound it in the kernel, and latch the unwitnessed suspend so hibernate cannot reclaim the disk over it

**Verdict up front: this NARROWS the window. It does not close it.** It moves the guard's life from ~120–195s to ~9–11 minutes, on a deadline flint sets and can state, instead of one the NFSv4 lease sets. Beyond that deadline the share still suspends under a live remote mount, and only `flint-hub-gateway` + a consumer-run keepalive closes the recovery half. Anyone who tells you a hub-side field closes (A) is wrong: at the wire, a hard node loss and a partition are the same event, and any rule that holds for one holds for the other for exactly as long as it cannot tell them apart.

---

## 1. What to build

Three mechanisms, one opt-in, no CRD change.

**(i) The witness — `nfs.connectedSessions`.** The lease is a *clock*, and a clock is silent for a crash and a partition alike. The hub holds a second fact that is not a clock: whether the client's TCP socket is still open. It is already in memory — `session_bound_conns: DashMap<SessionId, Vec<Weak<BackChannelWriter>>>` (`/Users/ddalton/github/flint/spdk-csi-driver/src/nfs/v4/dispatcher.rs:73-83`), whose `Arc` is owned by the connection-handler task, and the code already performs the liveness test `w.strong_count() > 0` at `:160`. `cleanup_expired_ids` (`/Users/ddalton/github/flint/spdk-csi-driver/src/nfs/v4/state/mod.rs:164-196`) does **not** touch that map — verified, and load-bearing. So `activeLeases == 0 && connectedSessions > 0` is "a client whose socket is still open and whose lease we reaped": partitioned, or dead in a way that emitted no FIN. Publish it and gate the existing `suspendWithSessions: false` opt-in on it.

**(ii) The deadline — `TCP_USER_TIMEOUT`, not SO_KEEPALIVE alone.** This is the refuters' most important correction and the design fails without it. `stream.set_nodelay(true)` at `/Users/ddalton/github/flint/spdk-csi-driver/src/nfs/server_v4.rs:327` is the only sockopt on an accepted socket, so a partitioned socket sits ESTABLISHED forever and the hold would be unbounded — the pre-`1b4af9b` bug with a new name. But **SO_KEEPALIVE governs an idle socket only.** A socket holding retransmitted-but-unacked data (the one carrying the hub's last reply to a node that died mid-I/O — and with the mandatory `nconnect>=2` that is always one of the four) is owned by the retransmission timer, whose deadline is `net.ipv4.tcp_retries2`: a node sysctl flint neither sets nor can see, ~924s at the default and routinely raised on storage-tuned nodes. `TCP_USER_TIMEOUT` caps *both* branches and is the sockopt this repo already reached for on the same failure — `/Users/ddalton/github/flint/spdk-csi-driver/src/nvme_recovery.rs:295`: "*becomes TCP_USER_TIMEOUT on the qpair socket — the KERNEL errors a blackholed connection once retransmitted data goes unacked that long*". Set it, and derive the documented bound from it.

**(iii) The latch — hibernate must not reclaim a disk over a departure nobody witnessed.** A socket is a process-local fact and the suspend *deletes the process*, so no TCP witness can survive into the hibernate decision. Refuter 3 proved the obvious follow-up ("gate `hibernatable()` on `activeLeases == 0 && connectedSessions == 0`") is not merely weak but **vacuously true in exactly the bad case**: the lease expiry already erased the client's persisted record, so the fresh verification pod restores zero clients, calls `end_grace()` (`state/mod.rs:112`), and reports 0/0 by construction. The memory has to be transcribed to the CR at the last instant it exists — the suspend transition — and read back from an annotation.

**And the half that actually recovers a long partition is operational, not code:** deploy `flint-hub-gateway` and run `POST /v1/projects/{id}/volumes/{v}/wake` every `keepaliveSecs` from the workload cluster. The brief's "(B) NO WAKE PATH" is too strong — the path is shipped (`/Users/ddalton/github/flint/spdk-csi-driver/src/lite_gateway/proxy.rs:490-573`, `arm_wake` at `:860-890`), needs one bearer token and no kube credential, and stamps on every call so it *is* the keepalive. It is `gateway.enabled: false` by default, ClusterIP-only, and the drill deployed none. It crosses a different network path from the mount, so it survives a partition of the NFS path — the only signal in the system that does.

## 2. After a crash / spot reclaim — one sentence

A clean shutdown that unmounted closes the socket and nothing changes at all, but an unclean node death — a spot reclaim whose drain could not `umount` a `hard` mount, a hard host loss, a force-terminate — is indistinguishable from a partition on the wire, so that share stays up for one bounded, kernel-enforced socket deadline (~9–10 minutes, then it suspends on schedule), and its *hibernate* is deferred until it is next woken or a client attaches.

Two corrections you need, because the leading design got them wrong in a way that matters: **a pod OOMKill, container restart or kubelet eviction closes nothing** — "Kubelet mounts once per node, so pods on one node share a kernel client and page cache" (`/Users/ddalton/github/flint/docs/flint-lite-for-agent-fleets.md:553-554`), so the mount is node-scoped and in the host netns; the node's client keeps renewing and those cases never reach the new gate at all. And on a pure-spot fleet the routine reclaim frequently *does* land in the silent bucket, because shutdown must unmount a hard mount and `umount.nfs` blocks. So state the property honestly: **this witness separates "clean drain" from "everything else", not "crash" from "partition".** It does not degrade to "never suspend again" — that is the whole point of the deadline — but it does mean the hold is paid on ordinary reclaims, ~9 minutes of one hub pod (100m CPU / 128Mi, `render.rs:108-109`), roughly two cents, once per event.

## 3. Does it cover hibernate?

**Yes — and it must, because hibernate is the strictly more destructive rung with the strictly weaker precondition.** Verified: `hibernatable()` (`/Users/ddalton/github/flint/spdk-csi-driver/src/lite_operator/hubstatus.rs:251-288`) reads only `rpo_clean == Some(true) && epoch.held` — no `phase == Serving`, no `import_refused`, no `sweep.completed`, no clients — while `suspendable()` (`:213-233`) checks four things. And step 1, the decision to *begin* hibernating, returns at `/Users/ddalton/github/flint/spdk-csi-driver/src/lite_operator/idle.rs:294-321`, before `hub_quiet` (`:357`) and before the sessions guard (`:365`), on two annotations and no live signal — the caller structurally cannot supply either, hardcoding `Err("the hub is scaled to zero")` at `reconcile.rs:1590`. Its escalation deletes the PVC, which mints a new `serverId` and invalidates every stateid the partitioned client holds.

The latch covers it: `chert.us/unwitnessed-suspend` blocks `BeginHibernate` indefinitely, and the escape is a wake or an explicit annotation removal. The asymmetry is deliberate — **the suspend hold is bounded because holding costs compute; the hibernate latch is unbounded because releasing costs a stale mount in a
cluster you cannot reach.** ⚠ **But holding does NOT cost "only the disk" —
that justification is false against shipped code.** A latched share sits in
`Suspended` PAST its hibernate rung, so in `settled_requeue`
(`reconcile.rs:259-268`) `after.saturating_sub(down_for)` is 0 and the
`.clamp(REQUEUE_PROGRESS, REQUEUE_PARKED)` floors it at **15s — 120× the
1800s parked rate, indefinitely**. The latch's real price is a per-reconcile
RATE term, which is the class the fleet-scale plan names as every blocker in
this operator. Cost the latch at fleet scale before building it. Note the suspend still happens under the latch, so the expensive half of the saving is still delivered.

## 5. Residual — what is still broken after this ships

1. **A partition longer than the socket deadline still suspends the share**, and with no gateway nothing wakes it. Same outage, ~9 minutes later. This is why the verdict is *narrows*.
2. **A hub restart before the witness ever fired defeats both the hold and the latch.** Partition at t=0, hub's own spot node reclaimed at t=10: restored clients get fresh leases, the ordinary lease guard covers ~90–120s, then 0/0 with `uptime` past the blind window ⇒ suspend with no latch ⇒ hibernate proceeds. Closing this needs the hub to persist "this client's session had an open socket at its last expiry" into the state DB. Not recommended today; it is the shape of the follow-up.
3. **Middleboxes.** Idle-60s keepalives refresh NAT/LB flow state, but any device that terminates TCP or enforces a hard connection lifetime kills the witness early ⇒ today's behaviour. Worth a line where `advertiseAddress` is documented.
4. **Version skew.** Against a hub without item 8, `connectedSessions` is `None` ⇒ no hold, no latch ⇒ exactly today. The operator renders the hub image, so this is transient, but a pinned older hub image silently disables the fix.
5. **`FLINT_PNFS_LEASE_SWEEP_SECS=0`** still pins every `suspendWithSessions: false` share awake forever, by a route none of this touches.
6. **NFSv4.0 clients have no sessions** ⇒ `connectedSessions` 0 ⇒ today's behaviour. Theoretical for flint (4.1/4.2), but a real hole in the field's meaning. Also note `connectedSessions` counts *sessions* while `activeLeases` counts *clients*; both are only ever compared to zero, but the docs must not imply one unit.
7. **With several clusters attached, the new gate rarely fires** — other clusters' leases keep `sessions_live == Some(true)` and the old guard holds. It matters when the partitioned client is the last live one, which is the drill's shape.
8. **The operator still has no metrics surface** (S1 has not landed; there is no `metrics.rs` in `src/lite_operator/`). The only new instrument is the `SuspendedWithActiveSessions` event, so every rate claim above is arithmetic, not measurement.
9. **`status.address` is still published while `IdleSuspended`**, naming an address with zero endpoints; and a wake still requires the operator to be reconciling (drill D6: 245s of a stamped annotation doing nothing with the operator at zero replicas).

Cost, stated plainly: **operator — zero new API calls, zero new polls, zero new writes, zero new watch events** (`connectedSessions` rides the `/status` GET `poll_hub` already makes, annotated in-tree as "the dominant API-server term"); **hub** — one `DashMap::retain` per `/status` render, which strictly *reduces* steady-state memory by pruning a leak; **network** — one probe per idle socket per 30s after 60s of silence; **wire** — ~40 bytes per status document.

## 6. Do not do these unattended

- **Do not flip the `suspendWithSessions` default to `false`.** There is a standing twice-validated recommendation to do so, and this change finally makes it *affordable* (the hold is now bounded), but it changes behaviour for every ladder-armed share in every existing fleet and belongs in its own release with its own note.
- **Do not enable `gateway.enabled` by default.** Turning on a Deployment plus a bearer-token surface is a larger blast radius than the defect; make its absence loud (item 4) and let an admin deploy it.
- **The `mountWarning` change (item 4) is wire-visible.** Harnesses that read a null warning as "safe to mount and forget" will start seeing a string — that is the intent, but it is a front-door contract change and belongs in the changelog, not a footnote.
- **The un-park convergence fix wakes every parked share whose `spec.idle` was removed, on the upgrade pass.** Count them first; there is no pacing machinery in the source (`grep -r 'token_bucket\|TokenBucket\|pacer\|Paced' src/` returns nothing — S11 is a plan, not code).
- **Item 9 must not ship without the drill leg that measures it.** A `TCP_USER_TIMEOUT` that silently did not take leaves an *unbounded* hold, which is the bug `1b4af9b` removed three days ago and re-shipping it is worse than the defect.

## 7. What I rejected, so it is not re-litigated

- **"Hold when a client vanished without a clean `DESTROY_CLIENTID`."** Rejected. Both paths converge on `ClientManager::remove_client(client_id)`, which takes no reason and logs identical text; counting them answers "was there a goodbye?" and nothing more, and an OOMKill, a spot reclaim and an `iptables -j DROP` all land in the same bucket. On a pure-spot fleet it degrades to "never suspend again". It is also a partial revert of **`1b4af9b`** (2026-08-19, shipped in v1.35.1), which added the periodic reaper precisely because a partitioned sole client held `activeLeases=1` for a **measured 770s** against a 90s lease. Nothing recommended here touches the reaper, the lease, or `activeLeases`; every new hold has an independent, shorter, kernel-enforced deadline.
- **Wake-on-connect (an EndpointSlice pointing a parked share's own address at the gateway, which speaks enough ONC RPC to arm a wake).** Genuinely closes (B) and is the strongest idea in the field, but not today: its arm predicate as proposed fires on bare lease-renewal COMPOUNDs — "an idle NFSv4 mount renews its lease forever" — so it re-creates "pin every mounted share awake" at a ~50% duty cycle; it makes an unauthenticated TCP connect a resource-allocating action; and its only cost mitigation is unbuilt pacing bolted to gateway **pod IPs** on a pure-spot fleet, whose failure mode is silent reversion to today's outage with a five-hour `FULL_APPLY_AFTER` backstop. If it is taken later: arm only on COMPOUNDs `nfs::activity::classify` would count (plus EXCHANGE_ID), and give the doorbell a stable address instead of pod IPs.
- **Declared tenancy (`consumers: Federated` + withholding the ladder until a wake lease exists).** The right *contract*, wrong economics: the withhold converts a large population from parked to permanently Active, and only parked shares can use the apply-skip gate (`reconcile.rs:1166-1171`) while Active shares requeue at `clamp(suspendAfterSecs,15,300)` instead of `REQUEUE_PARKED` 1800s — ~30× the reconciles and ~150× the applies per converted share, against a fleet whose operator already OOMKilled once at 3000 shares. Its enrolment latch is also disarmed permanently by any incidental file-API call (`arm_wake` is called from **two** sites: `proxy.rs:538` and `proxy.rs:706`).
- **A pure operator-side `sessionGraceSecs` timer.** Same shape as this recommendation but keyed on a timer the operator invents rather than a socket fact the kernel enforces — and as specified by both authors it is *inert on the drilled timeline*, because it patches an annotation and then reads it back off an unrefreshed local object in the same pass.
