flint-lean is installed in namespace {{ .Release.Namespace }}.

Declare a workspace:

  apiVersion: chert.us/v1alpha1
  kind: FlintLeanWorkspace
  metadata: { name: proj1 }
  spec:
    projectId: team-a/proj1     # DURABLE identity — the claim keys on
                                # this, never on the CR UID, so delete
                                # and re-apply ADOPTS its own data
    bucket: my-bucket
    keyPrefix: tenants/proj1
    endpoint: http://s3-proxy.svc:9000
    credentialsSecretRef: proj1-proxy-creds   # keys AWS_* verbatim
    floorSecs: 60               # the RPO contract
    maxFiles: 250000            # the measured v1 cap (0b)

  kubectl get flintleanworkspace proj1
  # PHASE Claimed | Adopted — or Refused, which means another project
  # holds that prefix's claim. The operator NEVER adopts a foreign
  # claim on the fly; resolve it explicitly.

Then give a pod the workspace as ONE volume — no label, no sidecar,
no Secret in the pod's namespace (the s3.csi.chert.us node driver from
flint-s3-csi-chart must be installed; the CR's spec.consumers names the
ServiceAccounts that may mount it, and spec.uid the uid the syncer
runs as):

  spec:
    serviceAccountName: agent          # listed in spec.consumers
    volumes:
      - name: ws
        csi:
          driver: s3.csi.chert.us
          volumeAttributes: { chert.us/workspace: proj1 }
    containers:
      - volumeMounts: [{ name: ws, mountPath: /workspace }]

The driver materializes the workspace before ANY container of the pod
(init containers included) starts, and drains it when the pod is
deleted. If the workspace is missing, Refused, or the ServiceAccount is
not a consumer, the pod stays ContainerCreating with a FailedMount
event naming the reason — it never starts ungated.
