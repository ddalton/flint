THE INVARIANT.  IndM1 == IndTypeOK /\ M1 with
  M1 == Inv_OneHolder /\ Holder /\ Cased /\ Mine /\ Ups /\ Off /\ Rescope
  Holder  (I1)  holder # "none" => w[holder].pc \in {claimed, cased} /\ On(holder)
  Cased   (I6)  pc = cased => every delete's inst is Nil
  Mine          deletes \cap uploads = {} /\ gone \subseteq uploads
  Ups           pc \in {scanned, claimed, cased} => (uploads \cup deletes) \cap unlinked = {}
  Off           st = "off" => w[s] = WriterInit
  Rescope = R1 (I7a) pc \in {consumed..cased} => sStage = none
            R2 (I7b) p \in unlinked /\ sStage = none => local[p] = baseline[p]
            R3  p \in unlinked /\ sStage \in {saved, mid} =>
                  local[p] = baseline[p]
                  \/ (p \in sDrop \ sKeep /\ baseline[p] = Nil /\ local[p] # Nil /\ sHeld[p] = local[p])
            R4  sStage = mid => \A p \in sDrop \ sKeep : baseline[p] = Nil
            R5  pc = pulling => sStage \in {none, saved}
The six beyond the plan's list (Mine, Ups, Off, R3, R4, R5) were read off the
actions while writing the step lemmas, and TLC-checked first
(MCLeanP1M1.tla, the M1*.cfg worlds, SUMMARY.txt) -- the house rule.

WHY EACH IS THERE (the step that needs it):
  Mine  Install's `Cased'`: InstallInst(s)[p] for p \in deletes is Nil only
        if p is not in gone and not in uploads \cap upDone (the IF chain), and
        then only with DeleteWinsPreserved -- the rule constant this
        milestone uses (its TLC world: LeanP1DeleteOutranked, which FIRES on
        Prop_DeleteSettles, gate 2026-10-04).
  Ups   UploadCopy's and Finish's `R2'`: a copy upload rewrites local[p] for
        p \in uploads, and Finish rewrites baseline on uploads \cap upDone and
        on landed deletes; an unlinked path is clean (R2), so it is in
        neither set at the scan, and from the scan on `unlinked` only shrinks.
  Off   Checkout: the one step without On(s); its tree is WriterInit, so
        every conjunct about it is vacuous (no "cased while off" argument).
  R3/R4 RescopeSecond's `R2'`: with sStage = mid, R2 says nothing about an
        unlinked path.  What is true there: the first half (RescopeUnciteFirst)
        dropped its baseline, kept its bytes and recorded them in sHeld, so
        the second half's RescopeUnlink test (sHeld # Nil, same Content)
        fires and the tree ends Nil = baseline.  R4 is what makes `local =
        baseline` and `p \in sDrop \ sKeep` incompatible with RescopeUnlink
        (baseline Nil there, so local Nil, so no unlink).  R3 carries through
        "saved" too: a Restart between the halves goes mid -> saved and
        keeps the tree, so "saved" can hold an uncited unlinked path -- the
        replay's KeepSet excludes it (baseline Nil) and the first half
        re-derives the same state.  `p \notin sKeep` is in R3's second
        disjunct because the second half's RescopeDrop is sDrop \ sKeep.
  R5    RPullSync in mid would rewrite baseline on owed paths and break R4;
        a pull starts only with sStage \in {none, saved} and nothing moves
        sStage while pulling.
The rule constants used: DeleteWinsPreserved (Cased at Install) and
RescopeUnciteFirst (R2/R3 at RescopeFirst/RescopeSecond).  Controls (plan
section 5): each dropped from Shipped must fail a named obligation; their
TLC worlds (DeleteOutranked -> Prop_DeleteSettles, NarrowUnlinkFirst ->
Prop_NarrowNeverDeletes) fire in the gate.  Plus M1's own control: Claim
without `holder = "none"` must fail Inv_OneHolder' at Claim.

THE PROOF SHAPE.  One generic lemma per conjunct (HolderWrite, CasedWrite,
MineWrite, UpsWrite, OffWrite, RescopeWrite / RescopeShrink, NarrowWrite),
each taking the step's new tree R and `\A t : w'[t] = IF t = s THEN R ELSE
w[t]` (WriteAny, from TypeOK alone) and a hypothesis on R's fields; a step
lemma reads R's thirteen relevant fields once (`<1>3 BY DEF <Step>W`) and
discharges each hypothesis from the reads, the guards and the conjunct for
s.  IndTypeOK' comes from M0's step lemma.  Steps that write no tree
(gateway, Sweep, Age, Reap, RLoad) use M1Keep.  The two action properties:
Prop_DeleteSettles is Cased at Finish (one obligation); Prop_NarrowNeverDeletes
is NarrowOK, proved with each step lemma (only Scan reaches pc = scanned
from consumed, and its deletes are ScanAbsent, dirty paths).
