TWO RIG DEFECTS THIS RUN CAUGHT, both of which produced a WRONG VERDICT
before they were fixed. Recorded because each would have been reported as
a finding about the code:

1. `pgrep -x flint-pnfs-mds` cannot match a process named
   `flint-pnfs-mds.UNFIXED` — `-x` is an exact match. The control arm's
   server DID start, the arm declared "SERVER DID NOT START" and exited
   BEFORE its cleanup, leaving that server holding port 20490. The next
   arm could not bind, and its client talked to the PREVIOUS arm's
   binary. The fixed arm reported DATA LOSS — the unfixed binary's
   behaviour, under the fixed binary's label.
   Fix: every arm copies its binary to ONE name (`mds-under-test`) so
   `pgrep -x` matches both, and asserts the pid on the port is the pid
   it started.

2. `sudo pkill -f flint-pnfs-mds` in the cleanup matched the SSH command
   line that contained that string, killing the session. Third time in
   this repo. Only `pkill -x <exact name>` is used now.
